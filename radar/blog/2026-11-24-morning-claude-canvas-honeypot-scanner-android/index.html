rounds: холст сессий Claude Code

krispuckett/rounds по описанию репозитория — локальный холст всего, что производят сессии Claude Code. README пишет, зачем он появился: автор вёл много сессий сразу и терял, что каждая сделала; теперь результат собирается в одном месте, и на нём можно оставить заметку. Кому: тем, кто запускает Claude Code на своём Mac. Сессии в облаке до холста не доходят. Нужны Mac, Node 20 или новее и Claude Code. Проба из README — npx github:krispuckett/rounds --demo: шесть публичных проектов автора и заметки, которые он на них оставил. Демо стартует в своей папке и настройку Claude Code не меняет. Установка — npx github:krispuckett/rounds init: программа добавляет MCP-сервер, skill и два хука и спрашивает перед каждым. Затем npx github:krispuckett/rounds открывает холст и подтягивает свежую версию, включая хуки. На холсте — экраны, страницы и push каждой сессии, разложенные по проектам. Заметку можно приколоть к экрану: сессия, которая это сделала, получает заметку, вносит правку и отвечает. Экраны сравнивают перетаскиванием, по дням можно отступить назад, сессию ищут по имени или по заголовку группы на шкале времени. Файлы, которые сессия меняла, лежат на листе рядом с экранами: файл открывают, читают правки построчно и видят, какие ещё сессии его меняли. README отдельно пишет, что Claude Code по умолчанию удаляет терминальные сессии через 30 дней; сделанное и каждая опубликованная страница остаются на холсте, даже если папку потом очистили. Приватность: всё лежит в ~/.rounds на Mac, сайты до этого каталога не достучаться. Чтобы разложить старые экраны по темам, Rounds спрашивает Claude Haiku через ваш же Claude Code и отправляет подпись экрана, имя сессии и имена файлов. Раз в день программа спрашивает GitHub, есть ли новая версия; с этим запросом ничего с холста не уходит, а "updates": false в ~/.rounds/config.json проверку выключает. Поле private в том же файле скрывает совпавшие проекты. Снять поставленное — npx github:krispuckett/rounds uninstall. Лицензия в README и в поле API — MIT, автор Kris Puckett. turingpot: honeypot для агентов

tracebit-com/turingpot по описанию — открытый honeypot, прототип для расследования ARTEX и других автономных атакующих фреймворков. README: сервис показывает простые задачи и записывает, как быстро посетитель их решает. Быстрые верные ответы — эвристика активности ИИ-агента. В журнале есть IP источника и, когда отпечаток доступен, JA4: его ищут в журналах других своих сервисов. README прямо пишет, что код на 100% сгенерирован ИИ, человек его прочитал, и сценарий прогнан от начала до конца на Cloudflare Workers. Кому: тем, кто подозревает, что организацию разбирает такой фреймворк, и хочет IP, окно времени и иногда JA4, чтобы проверить, доходил ли тот же клиент до своих сервисов входа. Проба: Node.js 22.12 или новее, из каталога проекта npm ci и npm run dev. Локальный адрес печатает Wrangler; README просит открыть ссылку Access inventory. Ответ HTTP 409 на первой задаче там назван намеренным. npm test гоняет тесты протокола и адаптера хостинга. Выкладка из README: Cloudflare Workers на бесплатном тарифе — npx wrangler login, затем npm run deploy; на Vercel репозиторий импортируют с пресетом Other и входящим vercel.json. По умолчанию третье верное решение пишет событие possible_ai_agent, двенадцатое — pagination_sequence_completed с тем же идентификатором сессии; в обоих есть затраченное время. Решить задачи, по README, может человек, ИИ-агент или скрипт, написанный под эти задачи. В проверках README модели гоняли напрямую, без обвязки агента, и отдельно гоняли ARTEX: в этих прогонах модель или агент брались за задачи и поднимали сигнал. Скрипт, написанный специально под протокол, тоже поднимал его в сквозных тестах на Cloudflare Workers и Vercel. Долю ложных срабатываний на живом трафике README называет неизвестной. На Cloudflare Workers Free поле ja4 пустое; отпечаток, по README, могут отдать Cloudflare Enterprise с Bot Management и Vercel на всех тарифах. README советует ставить сервис на поддомен той организации, которую проверяют, и оставить на основном сайте указатель на него. Лицензия MIT. safe-anything: сканер уязвимостей на Rust

erkamyaman/safe-anything по описанию API — быстрый сканер уязвимостей целиком на Rust: XSS, SQL-инъекции, утёкшие секреты, CVE зависимостей и настройки ИИ-агентов. README шире той же фразы: одна команда ищет это в своём коде, плюс рискованные настройки мобильных и облачных конфигов; у каждой находки есть строка, причина и правка. Кому: тем, кто хочет прогнать свой репозиторий и файлы настроек агента локально, до коммита или в CI, без аккаунта и без выгрузки кода. Проба: cargo install safe-anything или npx safe-anything ., затем safe-anything .. Конфиг не нужен. Код выхода 1, если нашлось что-то уровня high или critical, поэтому README предлагает ставить команду проверкой pre-commit или CI как есть. Отчёт для машины — --json, для GitHub code scanning — --sarif, без сети — --offline: проверка зависимостей тогда пропускается. Список правил — safe-anything --list-rules. Учитывается .gitignore; пропускаются node_modules, vendor, target, dist, build, виртуальные окружения и .claude/worktrees. README называет 74 правила: у каждого идентификатор CWE, категория OWASP и ссылка на страницу OWASP. Языки кода в таблице README — JS/TS, Python, Go, Java, Kotlin, PHP, Ruby, C# и SQL. Секреты в выводе скрыты. Зависимости сверяют по lock-файлам с OSV.dev: это единственный сетевой вызов, уходят имена пакетов и версии. Код не исполняется, поток данных по программе не прослеживается. README прямо пишет: чистый прогон значит, что эти 74 проблемы не найдены. Безопасность кода из этого не следует. Для агентов есть MCP-сервер: claude mcp add safe-anything -- safe-anything mcp и та же форма для Codex, плюс плагин Claude Code. winedroid: Android-приложения без системы

sohzm/winedroid по описанию API запускает Android-приложения в вебе, на Linux, macOS и Windows. README описывает экспериментальный слой совместимости с Android для macOS, Linux и браузера, по образцу Wine: APK без загрузки ОС Android. Раздел локальной сборки покрывает macOS и Linux, отдельный раздел — сборку для браузера. Отдельной инструкции для Windows в этом README нет. Написан на Rust: исполняет байткод DEX, воспроизводит поведение фреймворка Android и рисует интерфейс через Skia. В сборках для рабочего стола есть JIT Cranelift. Сборка WebAssembly гоняет тот же рантайм и ту же отрисовку в браузере, на интерпретаторе. Стадия в README — очень ранняя: часть приложений и сценариев запускается, совместимость ограничена, части API нет, приложения ломаются. Кому: тем, кто хочет открыть APK на macOS, Linux или в браузере, не поднимая Android. Проба в браузере из README — демо на winedroid.soham.sh/demo. Локально нужны свежий стабильный Rust и нативные инструменты C/C++. На macOS это Xcode Command Line Tools. На Linux ещё pkg-config и пакеты разработки FreeType и Fontconfig; для окна нужна сессия X11 или Wayland. Сборка из README: cargo build --release --locked --bin winedroid, запуск ./target/release/winedroid /path/to/app.apk. Данные приложения лежат в ~/.winedroid/default, другой каталог задаёт WINEDROID_PREFIX. Сборка для браузера: в PATH нужен emcc из Emscripten и Python 3, затем rustup target add wasm32-unknown-emscripten, scripts/build_web.sh и python3 -m http.server 4173 --directory web. APK выбирают или перетаскивают на страницу. В браузерной сборке данные пропадают при перезагрузке, нативные библиотеки Android .so и JIT Cranelift не поддерживаются. Таблица AppDB в README называет шесть приложений с оценками: Weather Overview 0.1 — Gold, Candle 1.7.1 — Silver, Open Notes 1.4.0, Currency 1.58, OpenCalc 3.2.0 и Meditation Timer 1.2.0 — Bronze. Этот выпуск приложения не запускал.
