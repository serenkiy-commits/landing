mintlify/agent-traffic в описании GitHub отделяет агентов, AI-краулеры, поисковые краулеры и ботов от людей. По README это проверенный датасет user-agent, заголовков и официальных источников верификации реальных агентов и краулеров плюс маленький классификатор. Пакет — @mintlify/agent-traffic, зависимостей нет, работает там, где есть fetch: Node, Bun, Deno, Cloudflare Workers, Vercel Edge. Скилл для агента ставится командой npx skills add mintlify/agent-traffic в Claude Code, Cursor, Codex и в других агентах, которых поддерживает skills CLI. Файл скилла — skills/agent-traffic/SKILL.md: он объясняет классификацию и использование пакета и датасета, от обработчика запроса до сохранённых логов.

Функция classify принимает user-agent, заголовки и реальный IP клиента. Категории из README: agent (продукт ИИ забирает страницу сейчас, для человека; виды assistant, coding, browser, unidentified), ai-crawler (компания ИИ собирает страницы заранее: training, ai-search, ingest), crawler (поисковик, вид search), bot (прочая автоматизация, включая impersonator и fake-browser), human и unknown. loadIpRanges скачивает опубликованные диапазоны IP OpenAI, Anthropic, Google, Perplexity, Apple, Microsoft, Common Crawl и DuckDuckGo. verified: true значит, что IP входит в опубликованные диапазоны оператора; verified: false — что запрос доказуемо не тот, за кого себя выдаёт. Кодинг-агенты вроде Claude Code README относит к машине пользователя, поэтому их по IP не проверяют. Проверка «поддельного браузера» включается флагом headersComplete, когда заголовки браузера доходят целиком по HTTPS. Отдельные регулярные выражения лежат в patterns по категориям agent, ai-crawler, crawler и bot. Датасет импортируется и как JSON: data/agents.json, data/http-clients.json, data/headers.json. onlyread: агент в браузере читает и не пишет

onlyreadai/onlyread в описании GitHub делает браузерных ИИ-агентов только-читающими: расширение Chrome отказывает в записи (отправка, пост, правка, удаление) до того, как запрос уйдёт из браузера. По README это режим read-only. Чтение проходит. Отправка, пост, лайк, правка, удаление и смена настроек отклоняются. Расширение — Manifest V3. Ставится из Chrome Web Store или распакованным zip из релиза: у релиза указан SHA-256 обоих архивов, сборка та же, что в магазине. Подходит Chromium, который ставит расширения Chrome. Firefox и Safari в README на сегодня нет: нужны API расширений и отладчика Chrome. В списке README — Edge, Comet, Dia, Opera, BrowserOS и другие.

По умолчанию охрана включена, пока в браузере работает ИИ-агент, и не мешает обычной работе. Режим Always в настройках Security стережёт всё время, и тогда запись блокируется и у человека; для него README советует PIN настроек. Сайты, которые агенту можно открывать, включают в настройках. Судья ИИ на выбор: вход в OnlyRead Pro или свой ключ OpenRouter либо Vercel AI Gateway. В таблице README у своего ключа плата идёт шлюзу за использование; у Pro — 1000 бесплатных запросов к судье, дальше тот же контур моделей на стороне сервиса. Цепочка из README: правила, декодер сайта, кэш вердиктов, затем судья. Методы, которые только пишут, отправки форм с переходом, загрузки и beacon отклоняются сразу. Сокеты, протокол которых известен, разбираются; неизвестные отклоняются. Приложения, где чтение и запись идут в один endpoint (в README — каналы синхронизации Google, server actions LinkedIn, GraphQL Facebook), декодер узнаёт операцию по имени. Судья отвечает на вопрос, меняет ли запрос данные на сервере. Второй моделью проверяется то, что первая не закрыла. Сомнение или недоступный судья означают отказ. Судье уходит адрес запроса и короткий фрагмент тела, пароли, токены и номера карт из него убирают; cookies, заголовки, ответы и страница ему не отправляются. README пишет, что расширение охраняет браузер, а не конкретного агента: расширения-агенты, ИИ-браузеры и фреймворки автоматизации. В таблице названы Claude in Chrome, ChatGPT in Chrome, Gemini in Chrome, Comet, Grok Bot, Dia, Opera Neon, Edge Copilot Mode, Browser Operator, BrowserOS, Browser Use и Playwright. Сайт, которого нет в списке, можно включить со страницы настроек или пунктом Guard this site. В README указано «проверено на 100+ сайтах», включая записи датасета Mind2Web (Deng et al., NeurIPS 2023, CC BY 4.0). Глубже, чтение за чтением и запись за записью, разобраны Gmail, Google Calendar, Linear, LinkedIn, Facebook, X, Telegram, WhatsApp и Reddit — список в docs/SITES.md. Пока агент работает, выключить OnlyRead или ослабить настройки из самого расширения нельзя. Человек у клавиатуры по-прежнему может отключить расширение в chrome://extensions; закрыть и это, по README, может только корпоративная политика Chrome. sakutto: перевод страницы моделью на устройстве

jammaru/sakutto в описании GitHub — расширение браузера для перевода на устройстве локальной моделью PLaMo: приватно, бесплатно, сервер не нужен. README называет его неофициальным расширением для Chrome и Firefox. Модель — PLaMo 3 Translate, прогон через закреплённую сборку wllama. Каждую переведённую строку пишет PLaMo: страница, которая ждёт модель, остаётся с исходным текстом. В Chrome переводчик Chrome используется только для пар, которых у PLaMo нет. Firefox работает только с PLaMo. README прямо пишет: проект не аффилирован с Preferred Networks, Inc. Веса модели в репозиторий и в пакет расширения не входят. Код свободный, MIT, рекламы и платных функций в README нет.

Установка из Chrome Web Store; сборка из исходников — Node.js 24 и pnpm 12, затем pnpm install. Chrome грузят распакованным из .output/chrome-mv3. Firefox 153 и новее (в README сначала Windows) — временное дополнение из .output/firefox-mv3/manifest.json, подробности в docs/FIREFOX.md. pnpm build:wllama собирает закреплённый коммит wllama d275dac в контейнере emscripten/emsdk:4.0.20. Wasm, воркеры и веса в git не коммитятся; pnpm build и pnpm zip не идут, пока эта сборка не проверена. В zip не должно быть весов, source map и host permissions на момент установки. Сочетания клавиш: страница, двуязычный вид, выделение, текст, который печатают. В Firefox по умолчанию Alt+Shift и буква, чтобы не забирать строку меню Windows. Поле ввода переводится той же моделью PLaMo, встроенный переводчик Chrome там не используется. PLaMo 3 Translate, по README, покрывает 53 языка в обе стороны. Ещё одиннадцать (cs, da, el, fi, kn, no, pt, ro, sv, tr, uk) переводит только встроенный переводчик Chrome, и только в Chrome; Firefox эти цели скрывает. Интерфейс самого расширения переведён на 14 языков, в списке есть русский. Каталог выбирает язык интерфейса браузера, запасной — английский.

Сетевой запрос встроенного движка — скачивание модели с Hugging Face. Экспериментальный локальный сервер в настройках (mlx_lm.server, LM Studio или другой OpenAI-совместимый процесс на этом компьютере) получает текст только на адрес, который задал человек. README помечает этот путь как экспериментальный: точность не гарантируется, и перевод может разойтись со встроенным движком. Разрешения: storage, unlimitedStorage (модель и кэш на устройстве), offscreen, activeTab, scripting, contextMenus. Доступ к сайтам запрашивается, когда включают автоперевод для сайта, а не на все сайты при установке. Движок по умолчанию — упакованный wllama, WebGPU или CPU.

kinetic: локальный движок для GGUF

Veloresearch/kinetic в описании GitHub — открытый движок, чтобы запускать ИИ на своём компьютере. README уточняет: написан на Rust, читает файлы GGUF (формат llama.cpp) и гоняет поддерживаемые модели на CPU и на GPU NVIDIA, AMD и Intel из одного бинарника. Платформы — Windows и Linux x86-64. macOS в FAQ README нет и не планируется. Лицензия кода — Apache-2.0; имя и логотип Kinetic README относит к товарным знакам Velocity, правила в TRADEMARKS.md. Документация — https://veloresearch.github.io/kinetic/.

Установка в README: скрипт PowerShell на Windows (права администратора не нужны) и install.sh на Linux. Скрипты качают последний релиз, сверяют SHA256SUMS и кладут kinetic в PATH: %LOCALAPPDATA%\Programs\kinetic на Windows, ~/.local/bin на Linux. Архив x86_64-cuda идёт через CUDA на NVIDIA, через Vulkan на любой GPU и на CPU; архив x86_64-cpu — только CPU. README советует брать cuda-архив, даже если GPU не уверены: он стартует на любой машине и падает на CPU. Нужен драйвер видеокарты, не CUDA toolkit. Бинарник Windows, по README, пока не подписан, SmartScreen может остановить первый запуск. Сборка из исходников — Rust 1.91 или новее, для ядер CUDA ещё toolkit 12.8 или новее: cargo install --locked --git https://github.com/Veloresearch/kinetic kinetic-cli. Образы Docker в репозитории есть (docker/Dockerfile и docker/Dockerfile.cuda, kinetic serve на порту 8080); опубликованные образы README относит к будущему. Python-пакет — kinetic-engine.

Команды из README: kinetic pull качает модель, kinetic chat открывает чат, в том числе по локальному пути к GGUF, если семейство в списке поддерживаемых. kinetic без аргументов смотрит компьютер и предлагает две-три модели. kinetic models показывает, что уже лежит в кэше Ollama, LM Studio и Hugging Face. Сервер — kinetic serve model.gguf, OpenAI-совместимый API на http://127.0.0.1:8080/v1. В README есть примеры клиента на Python и JavaScript, вызовы инструментов, response_format с JSON Schema и грамматика GBNF, эмбеддинги (/v1/embeddings) и реранк (/v1/rerank). Картинки для Qwen3.5 и Gemma 4 идут с --mmproj и только как данные в запросе: URL сервер не скачивает. Библиотека без сервера — Python (import kinetic), крейт Rust и заголовок C include/kinetic.h. Устройства: CPU на x86-64 с AVX2; NVIDIA через CUDA (RTX 20, GTX 16 и новее); Vulkan для AMD, Intel и NVIDIA. Vulkan на момент README закрывает Llama, Qwen2.5, Qwen3, Qwen3.5 и LFM3. --device auto пробует CUDA, затем Vulkan, затем CPU. Сеть, по разделу Privacy, появляется только у kinetic pull: телеметрии, проверки обновлений и аккаунтов README не описывает. Сервер слушает 127.0.0.1, пока не передан --host. Запросы со страниц сайтов отклоняются.
