agent-sim: симулятор iOS для агентов на Linux

Developing-Gamer/agent-sim в описании GitHub — симуляторы iOS для ИИ-агентов на Linux, агентский слой для x86Sim. README уточняет формулировку: на обычной Linux-машине, без Mac и без GPU. Симулятор, который x86Sim поднимает в виртуальной машине x86-64, агент получает как стенд: поставить файл .ipa, прочитать экран как текст, нажать, ввести текст, прокрутить и смотреть живую картинку в браузере. Для скриптов и CI README обещает одну командную строку, для Claude Code, Cursor, Codex и других агентов — MCP-сервер. Пример в README: agent-sim launch com.apple.Preferences и agent-sim snapshot печатают элементы экрана «Настроек» с метками вроде @e2, agent-sim tap @e2 нажимает выбранную кнопку. README отдельно пишет, что проект построен на x86Sim автора designgears: x86Sim с первого релиза запускает симулятор iOS от Apple на Linux, agent-sim — слой для агентов поверх него. Кому: тем, кто хочет проверять iOS-приложение агентом на Linux, а не на компьютере Apple. Ограничения из того же README. Статус — early: сквозной сценарий работает, шероховатости ожидаются, список того, что ещё не работает, лежит в docs/KNOWN_ISSUES.md. Машина из быстрого старта — x86-64, Ubuntu 24.04, 8 и больше процессоров, 16 ГБ памяти, 60 ГБ свободного диска. agent-sim setup README описывает как однократный шаг примерно на полчаса: сам x86Sim, рантайм iOS от Apple объёмом 8 ГБ и первый телефон. agent-sim up, по README, поднимает симулятор за 12–30 секунд в зависимости от процессора. Запись Safari в README — 60 кадров в секунду, GIF там же — 15. Этот выпуск эти длительности и частоту кадров не перепроверял. Лицензия Apache-2.0. songe: локальное обучение своей модели на простое

sous-labs/songe в описании GitHub — движок обучения для своей локальной модели на простаивающих ресурсах компьютера. README: моделью пользуются как обычно через opencode, pi или любой инструмент с интерфейсом, совместимым с OpenAI. Пока идёт работа, Songe замечает, что случилось после каждого действия модели: результат инструмента, ошибку, следующее сообщение. Когда агент молчит, Songe учит модель это предвидеть. Новая версия подключается, только если проходит свои проверки, и ничего не покидает машину. Два режима README называет Dreams. Quick Dream за минуты дописывает предпочтения в инструкции модели. Deep Dream обучает саму модель, пока человека нет. Если новая версия на своих разговорах не лучше, она не встаёт; откат README описывает как один щелчок к любой прошлой версии. Запуск только когда агент простаивает, память свободна и с батареей всё в порядке; как только человек возвращается, обучение останавливается. Приватность в README: без аккаунта, без телеметрии, без облака; свои инструменты Songe не запускает. Кому: тем, кто уже работает с локальной моделью и хочет, чтобы она училась на поправках и ошибках инструментов, не отправляя переписку наружу. Установка в README — Python 3.11 или новее, uv tool install songe или pipx install songe, затем songe init. Оба способа, по README, кладут Songe в отдельное окружение: оно нужно фоновой службе. Для macOS README начинает отдельный путь через Homebrew, tap sous-labs/tap. Лицензия Apache-2.0. deslop-please: опиничный линтер для Rust

deterministic-machines/deslop-please в описании GitHub коротко: вернуть коду рассудок. README называет проект опиничным линтером, который убирает неряшливый код, и опирается на книгу Джона Оустерхаута «A Philosophy of Software Design»: глубокие модули, узкие интерфейсы. Язык репозитория — Rust, установка в README — cargo install deslop-please, пакет отмечен значком crates.io. Образец вывода в README — диагностика field-leak: поле структуры известно снаружи своего модуля, линтер печатает места вызова и показывает, какие поля утекли, а какие остались внутри. Тот же README показывает, как заглушить замечания: deslop-please --update-allow .deslop-please.allow, затем запуск с --allow. Кому: тем, кто пишет на Rust и хочет машинную проверку «узкий интерфейс, глубокий модуль», а не только стиль форматирования. Ограничение заложено в подаче: правила — позиция авторов, а не нейтральный стандарт оформления. Закрывающая строка образца в README — «65535 errors, well done!»; это текст примера, не замер этого выпуска. Лицензия MIT. xikhar/papercraft в описании GitHub — скилл агента для игр, интерактивных сцен, веб-страниц и анимаций в рукодельном стиле pop-up papercraft. Это не библиотека: README учит методу и несёт приёмы уже выпущенной игры на three.js. Кадр, по README, должен читаться как снятый бумажный макет: матовая бумага, каждый принт — слоёный коллаж с контрастными акцентами, тонкий тёмный обрез со светлой кромкой на освещённой стороне, мягкие тени, подкрашенные цветом мира, плотный мир из крупных кусков, макрообъектив с наклоном и сдвигом оптической оси сверху вниз, спокойное движение петель и тихие звуки бумаги. Типы конструкций, которые README предлагает расширять: кресты с прорезями, слоёные плоскости, складные коробки и призмы, купола, печатная вода, настилы, мосты и лестницы. Отдельно — как бумага двигается и звучит, как собрать персонажа, чьи карточки не врезаются друг в друга, и цикл «замерил и покритиковал». Мир задают промпт и референсы: снимок бумажной модели может быть целью по виду, фото, набросок или мудборд задают тему, агент пересобирает её в бумаге.
