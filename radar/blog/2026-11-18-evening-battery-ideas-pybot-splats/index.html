Wireless Battery: заряд на панели задач

krisgfx9/Wireless-Device-Battery-Monitor в описании GitHub — приложение панели задач и трея Windows 10/11: уровень батареи беспроводных мышей, гарнитур, клавиатур и контроллеров (Logitech, Razer, SteelSeries, Corsair, HyperX, Glorious, DualSense, Xbox, Bluetooth) без программ вендоров. README называет его Wireless Battery: обычный C++/Win32, около 350 КБ и около 2 МБ оперативной памяти, без среды выполнения и без фоновой службы. Установщик не просит права администратора. Программа читает устройства сама, через HID++ и вендорские HID-отчёты. G HUB, Synapse, iCUE, GG и NGenuity можно не открывать; если они уже запущены, README пишет, что конфликта нет. В комплекте HeadsetControl. На панели по умолчанию значок и процент. Цифра краснеет на 15% и ниже, в трее в этот момент уведомление о низком заряде. Синяя молния — зарядка, приглушённый текст — устройство спит и показан последний уровень. Уровни обновляются раз в 60 секунд, сразу при подключении устройства и при пробуждении компьютера. Язык интерфейса следует языку Windows, в списке есть русский, другой выбирается в меню. Файл для установки — WirelessBattery-Setup со страницы последнего релиза, либо портативный zip с WirelessBattery.exe. Подписи у файла нет: Windows может предупредить о запуске, README в этом случае указывает «More info → Run anyway» или сборку у себя через make или build.bat. Запросы к устройствам README описывает как чтение: неизвестным устройствам программа не пишет. В сеть она выходит из одного окна, «Request support for a device», и только после кнопки Send. Рядом README описывает экспериментальный трей для Linux на GTK4 и hidraw: для доступа к HID нужно правило udev, а Bluetooth, HeadsetControl и часть вендоров отнесены к следующим фазам.

Кому: тем, кто на Windows хочет видеть заряд мыши, гарнитуры, клавиатуры или контроллера на панели задач и не держать для этого программу вендора. Язык C++, лицензия GPL-3.0. README пишет «GPL-3.0 or later»: изменённую программу, которую распространяют, нужно выпускать под той же лицензией и с исходным кодом. 3744 звезды на 18.11.2026, 21:22 МСК, последний push 18.11.2026. Spaceship: идеи в реальном времени

chuanqisun/spaceship в описании GitHub — «Steer your ideas in realtime». README называет проект Spaceship IDE и показывает, какими ручками крутить текст идеи, когда генерация станет быстрой и дешёвой. Четыре приёма: монитор фокуса (что модель сейчас держит во внимании и куда из-за этого смотреть человеку), замок внимания (удержать фразу, чтобы сместить дальнейший текст), рули будущих векторов (разложить задачу на составляющие, подкрутить каждую и собрать снова) и повторная генерация (листать другие продолжения). Попробовать можно в браузере: chuanqisun.github.io/spaceship. Живой режим README подключает ключи Cerebras и Gemini; ключи остаются в local storage браузера, README прямо пишет, что это на свой риск. Когда основная ручка едет назад, будущий текст очищается, а текущие запросы отменяются: README связывает это с упреждающей генерацией и сбросом кэша. Автор пишет, что большую часть кода собрал в Claude Code, а интерфейс правил сам, и относит проект к шагу в сторону диссертации в MIT Media Lab. Фразу про 60 кадров в секунду README ставит как догадку о будущем моделей, не как замер этого демо.

PyBot: чатбот из правил

huggingface/pybot в описании GitHub — «PyBot: a chatbot written in pure Python by a swarm of agents. No weights, no training, just rules.» README спрашивает, как далеко уйдёт чатбот на правилах, если правила пишет рой агентов, а не человек, как у ELIZA. В коде — ветки if-else, регулярные выражения и таблицы, без весов и без обучения. README пишет, что рой из более чем 1000 агентов собрал и оценил более 5000 версий, а доля побед на SmolTalkBench, где судья-модель сравнивает ответ с эталоном, выросла с 0% до 26%, и ставит это рядом со SmolLM-360M-Instruct. Этот выпуск бенчмарк не повторял. Сам чатбот README оценивает примерно в 640 тысяч строк, тесты, которые написали агенты, — в 550 тысяч. На каждый ход модули в bot/modules/ предлагают ответ, арбитр bot/modules/arbiter.py выбирает один. Общие части README называет так: разбор реплики, память диалога, база фактов и сборка фразы. Запуск: Python 3.8 или новее, пакеты и модель не нужны. Клон репозитория и python -m pybot открывают чат в терминале; /reset начинает диалог заново, /exit выходит. README пишет, что старт занимает несколько секунд из-за объёма кода, а ответ — около секунды. Один вопрос без чата: python -m pybot -p и текст. Тот же чат в браузере README указывает на пространство Hugging Face: у ответа там видно, какой модуль его дал.

Кому: тем, кто хочет поговорить с чатботом без скачивания модели и готов читать правила вместо весов. Язык Python, лицензия Apache-2.0, 809 звёзд на 18.11.2026, 21:22 МСК, последний push 16.11.2026. Репозиторий на момент снимка не был архивным.
