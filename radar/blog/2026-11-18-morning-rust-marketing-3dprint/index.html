rust-anything: перенос по записи поведения

erkamyaman/rust-anything в описании GitHub переписывает приложение на Rust по частям и на каждом шаге сверяет кусок с записанным поведением исходной программы. В описании названы CLI, HTTP-серверы и библиотеки на TypeScript, Python, C, Go, Ruby и Java. README добавляет Node.js к TypeScript и JavaScript и помечает PHP и C# как preview: для них уже есть запись и проигрывание целого CLI или сервера, мост отдельных единиц README относит к следующему шагу. Код на Rust пишет агент или человек. README прямо говорит, что rust-anything код не переводит: он показывает, куда уходит время, в каком порядке переносить, собирает мост, чтобы остальной код звал Rust прежним API, записывает поведение и ставит gate, после которого шаг считается сделанным. Запись покрывает не всё. README выносит это в отдельный раздел: входы, которых не было в записи, расхождения регулярных выражений, то, что меняется между запусками, числа с плавающей точкой, побочные эффекты вне вывода и другую платформу. Проект README называет независимым: он не связан с Rust Project и Rust Foundation, слово Rust — товарный знак Rust Foundation.

Как попробовать из README. cargo install rust-anything, затем rust-anything setup. Setup регистрирует инструмент у Claude Code, Codex, Cursor и Gemini CLI. По таблице README Claude Code и Codex получают MCP-сервер и скилл, Cursor и Gemini CLI — MCP-сервер. Повторный запуск README называет безопасным, --remove снимает свои записи и оставляет чужие настройки. Для JavaScript README даёт npm install -g rust-anything — тот же бинарник. Если Rust ещё нет, готовые файлы для macOS, Linux и Windows README указывает во вложениях каждого GitHub release. В Claude Code README отдельно описывает установку плагином: MCP и скилл, CLI при этом должен быть в PATH. В README есть таблицы сравнений скорости и счётчики записанных случаев по прогонам автора. smoothstone: деталь по рецепту

baney75/smoothstone в описании GitHub — скилл и CLI, с которыми небольшая локальная модель вроде LFM3-1.7B делает детали для 3D-печати по словам или по картинке, в том числе если контекст модели уплотнили. README описывает приём так: модель не пишет геометрию. Она выбирает проверенный рецепт и подставляет размеры из запроса или картинки, а команда stone собирает деталь, проверяет, что её можно напечатать, и пишет шаги на диск. Каждое сообщение stone заканчивается строкой, что запустить дальше. stone status печатает эту строку снова вместе с запросом, рецептом, размерами и последней сборкой, так что модель, которая всё забыла, продолжает с неё. Сборка идёт через OpenSCAD с бэкендом Manifold. Проверки README перечисляет: замкнутая поверхность, одно тело, плоскость на столе, первый слой, толщина стенок, свес не круче 45 градусов и размер, который обещал рецепт. Если проверка не прошла, stone называет одну настройку и команду, которая её меняет. Картинку README пускает контуром для брелока, формочки и вывески и картой высот для литофании и рельефа; чтобы картинка пошла в дело, модели не обязательно на неё смотреть.

Рецепты README перечисляет: fan_guard, panel, cable_comb, vase, planter, gridfinity_bin, phone_stand, hook, spur_gear, box, keychain, cookie_cutter, sign, lithophane и relief. Каждый, пишет README, печатается без поддержек, примеры по умолчанию собираются и проверяются в CI. Уровень задают STONE_TIER или tier в stone.toml. Карточка S — модели около 3B и меньше только выбирают рецепт и числа. M — около 4B–30B ещё выбирают вид: стиль, узор, скругление, текст. L README отдаёт крупным моделям: они пишут новые рецепты на OpenSCAD с BOSL2 и библиотекой stone. stone status повторяет правила карточки, чтобы они вернулись после уплотнения контекста. Как поставить из README: нужны uv, OpenSCAD 2026 или новее (ночной сборке README приписывает бэкенд Manifold) и potrace для картинок. Дальше клон репозитория, uv tool install -e . и stone status. OpenSCAD README ищет в STONE_OPENSCAD, затем в PATH, затем в vendor/openscad/AppRun. Скилл — папка skill. README даёт символическую ссылку в каталог скиллов Claude Code, Codex и pi. Для локальной модели на llama.cpp README предлагает один инструмент stone, который запускает командную строку, и файл skill/tiers/S.md в системном промпте. В README есть свой прогон LFM3-1.7B, логи в LOG.md и наборы в evals. Этот выпуск прогон не повторял и доли из README в текст не переносит. Лицензию кода README называет MIT. BOSL2 в vendor/BOSL2 — BSD 2-Clause. Картинки кота, кролика и дерева в examples/images — Material Design Icons, Apache 2.0. Поле homepage в API на момент снимка пустое.
