openset-llm: 27B на CPU без видеокарты

opensetlabs/openset-llm в описании API — быстрый локальный вывод LLM на обычных процессорах: без GPU, 8 ГБ памяти, сервер, совместимый с OpenAI. README уточняет, что сегодня движок запускает одну модель: Qwen3.8-27B в троичном виде PrismML, Bonsai-2-27B, файл 5.95 ГБ, на x86 с AVX-512. Это набор новых ядер и патчей рантайма поверх форка llama.cpp от PrismML: install.sh накладывает их на закреплённый коммит e3de715. Сервер говорит на API OpenAI, поэтому уже существующий клиент ходит на http://127.0.0.1:8080/v1 без смены протокола. README называет соседний проект opensetlabs/openset-tts для речи; этот выпуск его API не снимал. Быстрый путь README требует AVX-512 VNNI и VBMI: Intel Xeon Ice Lake и новее, AMD Zen 4 и новее, включая Ryzen 7000 и 9000. У Intel Core 12-го поколения и новее этого набора нет, README относит их к более медленному запасному ядру форка. Apple Silicon install.sh не собирает и отсылает к Metal-сборке PrismML; Intel Mac тем же скриптом не поддерживается. Windows README проводит через WSL2 и просит клонировать в домашний каталог Linux, не в /mnt/c. Команда для чата: клон и ./start. Первая команда проверяет машину, собирает движок и скачивает модель (README пишет около 7.3 ГБ), затем открывает страницу http://127.0.0.1:8080. ./install.sh --check смотрит CPU и свободную память до скачивания. Скрипт отказывается работать ниже 8 ГБ RAM и на время подготовки просит около 15 ГБ свободного диска; после подготовки README называет 6.2 ГБ. Для разработчиков: ./serve — один пользователь, ./serve --multi 4 — несколько запросов сразу, ./serve --no-webui — только API. Пример Docker публикует порт только на 127.0.0.1:8080 и помечает образ как без аутентификации, для этой машины. Цифры скорости в README — замеры авторов, этот выпуск их не повторял. Заголовок README: 17–20 токенов в секунду для одного пользователя на машине 8 vCPU и 8 ГБ Ice Lake и около 4× к следующему из проверенных ими движков. В таблице прогона 11.11.2026 медиана ./serve — 19.67 ток/с против 4.58 у ik_llama.cpp и 3.16 у форка PrismML, те же промпты и та же машина. README отдельно пишет, что модель троичная, а сравнение с полной точностью лежит на карточке PrismML. Спекуляция, по README, меняет ответ только на почти равных вариантах: жадные ответы побайтно совпали с обычным декодированием на 17 из 24 промптов бенчмарка. Контекст по умолчанию — 4096 токенов: на 8 ГБ полный контекст со спекуляцией оставляет около 0.2 ГБ свободно. Веса README называет Apache 2.0 и пишет, что они скачиваются с Hugging Face, а в репозитории их нет. Лицензия кода — MIT, уведомление авторов ggml README сохраняет, кредиты относит к файлу NOTICE. Лицензия в снимке — MIT, язык — C++. Темы снимка: ai, avx512, cpu-inference, edge-ai, gguf, inference-engine, llama-cpp, llm, llm-inference, local-ai, local-llm, no-gpu, on-device-ai, openai-api, openai-compatible, quantization, qwen, self-hosted, speculative-decoding, ternary. Sessionly: журнал сессий на своей машине

KIvanow/sessionly в описании API — нейтральный к лаборатории локальный журнал сессий Claude Code, Codex, Cursor и Grok: что они сделали, сколько это стоило и что уцелело. README держит журнал на своей машине: какие инструменты запускались, какие файлы менялись и какая была цена, а затем считает, сколько строк агента ещё лежит в файле и сколько осталось в пул-реквесте после ревью. Делиться README предлагает по желанию: пока сервер не подключён, наружу ничего не уходит, а исходный код не уходит и после подключения. Снимок демо в README датирован 25.11.2026 и снят с собственного репозитория Sessionly: Claude Code — 21 сессия и $1,207.32, Grok — 13 сессий и $53.23, Codex — 3 сессии и $0.25, Cursor — 2 сессии без цены; всего 39 сессий, $1,260.80 и 63% строк, которые README ещё видит на месте. Рядом README пишет, что 9 из 39 цен — оценки, у трёх сессий цены нет, это один репозиторий и один разработчик за тринадцать дней, запись этой работы, а не бенчмарк агентов, и что демо обновляется каждый день, так что цифры уже сдвинулись. Этот выпуск демо не открывал. Установка: бинарник релиза для Linux и macOS или cargo install sessionly при Rust 1.89 или новее. Запись сессии ложится в SQLite по пути ~/.sessionly. Журнал README называет производными данными: удалить его и собрать заново можно командой sessionly sync --force. Облачные сессии Claude Code, Cursor и Codex README ловит хуками репозитория: sessionly install --repo. У своего сервера входа README нет: кто до него дошёл, тот и администратор, поэтому README просит держать его в сети, которой вы доверяете. Всё вне каталога ee/ README лицензирует Apache-2.0: бинарник, сервер и панель, ключ лицензии не нужен. Каталог ee/ закрыт файлом LICENSE-EE: функции Business и Enterprise и работа Sessionly как сервиса для многих организаций, включая регистрацию и вход через Google или GitHub. Obituary: срок жизни для файлов агента

woodfishhhh/obituary в описании API — корзина для ИИ-агентов: файлы, которые агент оставляет, уходят сами, когда истекает срок, а то, что агент удалил, семь дней можно вернуть. README раскладывает это на команды. obit add debug.log 2h хоронит файл, когда время вышло; obit bury хоронит сразу; obit resurrect возвращает на место и, по README, не затирает то, что уже лежит по этому пути; obit purge стирает по-настоящему то, что пережило срок хранения. Кладбище по умолчанию держит записи 7 дней. Запись помнит серийный номер тома и 128-битный идентификатор файла, поэтому переименованный файл README всё ещё находит, а чужой файл на старом пути не трогает. obit init добавляет Obituary в инструкции агента: файл OBIT.md, Agent Skill, MCP по желанию. Агент помечает отладочные скрипты, логи и снимки экрана командой obit mark, берёт временный каталог через obit mktemp и хоронит сомнительное через obit bury. Автоматическая регистрация по умолчанию выключена. Если её включить, README не регистрирует зависимости, результаты сборки и кэши ни в одном из трёх режимов и не трогает файлы, которые отслеживает Git. Сторож удаления, когда он включён, останавливает rm -rf, git clean и Remove-Item агента и подменяет их командой obit; README пишет, что обходы вроде find -delete и xargs rm тоже останавливаются. Перед тем как obit rm что-то тронет, README проверяет путь на диске, а не только текст команды, и отказывает корням дисков, системным каталогам и профилю пользователя. На Windows README отдельно останавливает удаление внутри обратных кавычек и $(…) в командах Codex, даже если фрагмент в кавычках: там команда проходит через ещё одну оболочку. Платформы README: Windows 10 и 11, macOS, Linux на x64 и ARM64. Установка: Scoop или install.ps1 на Windows (winget README помечает как на ревью), Homebrew или install.sh на macOS, install.sh на Linux. Лоток, маленькое окно, меню проводника и даты в Explorer README относит к Windows; окно и лоток на macOS — к универсальному DMG, на Ubuntu 24.04 amd64 — к пакету deb. Языки интерфейса командной строки, лотка, окна и меню README называет английский и упрощённый китайский; в репозитории при этом лежит перевод README на русский, README.ru.md. Схема агентов в README называет Claude Code, Codex, Cursor и длинный ряд других клиентов, а файл docs/agents.md README описывает как покрытие 30 агентов; этот выпуск тот файл не открывал.
