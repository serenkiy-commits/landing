superbot: боты на своей VPS

davidondrej/superbot в описании GitHub — open-source, self-hosted альтернатива Grok Bot. README раскладывает это так: у бота есть имя, одна роль, свой чат и память в обычных файлах. Боты работают на агенте, который уже стоит на машине, — Claude Code, Codex или Pi, — каждый через свой небольшой адаптер. Общий Linux на вашей VPS хранит файлы и входы между задачами. Боту можно задать расписание, боты передают работу друг другу. README помечает статус как ранний: чат, память, расписание и передача между ботами уже есть, пауза перед рискованным действием и управление компьютером — дальше. Проект не связан с xAI, имя Grok README называет товарным знаком xAI. Сервер, адаптеры и CLI написаны на Rust; веб-код README оставляет там, где он нужен браузеру. Сборка из README: cargo build --release даёт botd и botctl.

Кому: тем, кто хочет команду агентов на своём сервере, а не в чужом окне. Язык Rust, лицензия MIT, 229 звёзд на 17.11.2026, 06:25 МСК, последний push 15.11.2026, 21:50 МСК. Репозиторий создан 15.11.2026 и на момент снимка не был архивным.

git-twig: worktree, которые не раздувают диск

leostera/git-twig в описании GitHub — лёгкие git-worktree для агентов. README обещает дешёвые worktree и «до 97% меньше места на диске»; этот выпуск цифру не перемеривал. Нативный copy-on-write README ограничивает macOS на APFS и Linux на Btrfs или XFS с reflink, и только для текущего HEAD исходного checkout. Другие ревизии, неподдерживаемые файловые системы, включая обычный ext4, и часть правил checkout идут через git worktree. Копируются зафиксированные файлы; локальные правки и игнорируемые файлы README не переносит. Для агента есть команда git twig skill. Установка из README: формула Homebrew или cargo install git-twig --locked, нужны Rust 1.95+ и Git 2.40+. Улучшения checkout вроде text=auto eol=lf README относит к разработке: в опубликованный релиз v0.3.0 они не входят.

Кому: тем, кто плодит worktree под параллельные сессии агента и упирается в место на диске. Язык Rust, лицензия MIT, 183 звезды на 17.11.2026, 06:25 МСК, последний push 17.11.2026, 01:24 МСК. Репозиторий создан 15.11.2026 и на момент снимка не был архивным.

inside-llm: где две квантизации расходятся

manuelgscom/inside-llm в описании GitHub показывает, где две квантизации GGUF расходятся токен за токеном и что отсекает каждый сэмплер. README: один нативный бинарник на llama.cpp поднимает свою страницу. Счёт идёт на машине пользователя, без аккаунта, ключа и телеметрии. Можно открыть одну GGUF или две — две квантизации либо базу и дообучение — и видеть вероятность токена, отброшенные варианты и место, где тексты расходятся. Сессию можно записать и потом проиграть на статической странице без движка и GPU. Записанные сессии README выкладывает на manuelgs.com/en/inside-llm/demo/. Пакеты README перечисляет для Linux и Windows, сборки CUDA и Vulkan: кроме драйвера GPU ставить ничего не нужно. Движок README описывает как C++17, страница внутри бинарника — Svelte. Поле языка в GitHub API на момент снимка — TypeScript. Код README относит к MIT; в пакеты входят llama.cpp и другие компоненты, их уведомления README выносит в THIRD_PARTY_NOTICES. Проект не связан с авторами llama.cpp и загружаемых моделей.

Кому: тем, кто выбирает квантизацию локальной модели и хочет видеть расхождение, а не только размер файла. Лицензия MIT, 86 звёзд на 17.11.2026, 06:25 МСК, последний push 16.11.2026, 20:42 МСК. Репозиторий создан 15.11.2026 и на момент снимка не был архивным.

TelemetryCleaner: операторские пакеты на Android

Eynnzerr/TelemetryCleaner в описании GitHub — приложение на Shizuku: без root находит и снимает предустановленные на китайских прошивках Android модули сбора данных вроде SystemHelper и RegService. README сразу оговаривает, что оператору для ввода терминала в сеть и диагностики часть данных нужна, а проект — про механизм пакетов Android. Нужен Android 10 или новее. Shizuku запускают по ADB или, с Android 11, беспроводной отладкой. Дальше приложение показывает, в каком пространстве компонент стоит и какие разрешения объявлены, и даёт снять или вернуть отмеченные пакеты. Снятие идёт в выбранном пространстве и чистит там данные компонента; восстановление берёт APK, который сохранила система. README прямо пишет ограничение: на vivo OriginOS пакет com.vivo.devicereg в защитном списке системы, без root его не снять. Автор проверил SystemHelper и компоненты OPPO; часть других производителей, пишет README, подтвердили читатели. Сборки README указывает в GitHub Releases.

Кому: тем, кто на своём Android хочет увидеть операторский пакет и решить, снимать ли его. Это не обход чужого сервиса и не массовая регистрация.
