DataCat: своя наблюдаемость

replit/datacat в описании GitHub — «Self-hosted observability: metrics, logs, traces, dashboards and alerts. Stores data in PostgreSQL or ClickHouse. Accepts OpenTelemetry data.» README называет DataCat системой на своей инфраструктуре: метрики, логи, распределённые трейсы, дашборды, инфраструктура и алерты. Хранение — PostgreSQL; телеметрию README предлагает складывать в ClickHouse, если так выбрать, и отсылает к docs/SELF_HOSTING.md. Приём — OpenTelemetry и трафик, совместимый с агентом Datadog. Отдельный облачный аккаунт README не требует. В списке возможностей: обозреватель метрик, формулы, дашборды и карта хостов; поиск по логам с фасетами, live tail и связь с трейсом; каталог сервисов APM, обозреватель трейсов и waterfall; мониторы метрик, логов и трейсов с уведомлением в webhook или Slack; организации, локальные учётки, одноразовые приглашения и ключи API. Один процесс в production отдаёт API, веб-интерфейс, установщик и загрузки. Быстрый старт README собирает через Docker Compose: Docker Engine с плагином Compose, Git и OpenSSL, затем клон, копия .env.example в .env, свои POSTGRES_PASSWORD и SESSION_SECRET, chmod 600 .env и docker compose up -d --build. Интерфейс README открывает на http://localhost:3000. Токен первичной настройки печатается в логе сервера, если не задан DATACAT_SETUP_TOKEN. Перед приглашением коллег и установкой агентов снаружи README просит выставить PUBLIC_URL на внешний HTTPS-адрес. Бинарники агента и пакеты SDK README относит к отдельным файлам релиза: их, вместе с SHA256SUMS, кладут в downloads/. Сборка из исходников: Node.js 22.15 или новее, pnpm 10.11.0, PostgreSQL 14 или новее. Агент README собирает на Go 1.26.11 или новее. Приём README описывает так: Datadog Agent 7.56.2 и 7.85.4 — проверенные прогоны метрик, логов, check runs и трейсов; версии 7.57–7.84 по отдельности не проверялись, и агент, чей формат трейса DataCat не читает, получает 422, а не тихий 202. OpenTelemetry Collector и SDK идут по OTLP/HTTP на /v1/traces, /v1/metrics и /v1/logs, те же пути есть под /otlp/v1/. Вход — локальные учётки email и пароль, участники заходят по одноразовой ссылке. README прямо пишет, что проект независимый и не связан с Datadog, Inc.: имя вендора стоит только как описание совместимости протокола. Лицензия Apache-2.0; зависимости сохраняют свои лицензии.

Кому: тем, кто хочет метрики, логи, трейсы и алерты на своей машине и уже шлёт данные по OpenTelemetry или через агент Datadog. На что обратить внимание: секреты в .env, токен настройки и PUBLIC_URL до того, как инстанс смотрит наружу. Таблица совместимости агента Datadog — формулировка README, этот выпуск её не повторял. motlab: видео как код

staryone/motlab в описании GitHub — «Video as code: canvas scenes rendered with WebCodecs in headless Chrome, a review viewer, and agent skills that build the video from your references.» README описывает движок, где каждая сцена — страница с функцией renderAt(t), кадр на момент времени t. Страницы смотрят в веб-просмотрщике покадрово и собирают в MP4 в headless Chrome. Агенту отдают папку референсов — логотипы, скриншоты, съёмку, шрифты, музыку, голос — и короткое задание; он пишет сцены, открывает просмотрщик и правит по заметкам. Моделей картинки или видео README не использует: кадр рисует код в Chrome. Заметки на кадре, рамке или отрезке времени пишутся в selection.json, агент читает их по номерам. Версии проекта в просмотрщике стоят рядом. Экспорт — MP4 720p, 1080p, 1440p или 4K, со переходами, музыкой и голосом сцен. Кадры кодирует WebCodecs внутри страницы, в ffmpeg они уходят уже потоком: ffmpeg копирует потоки, склеивает части, ставит цветовые метки и добавляет звук. Второй скилл, motlab-assets, собирает наборы иконок, иллюстраций, ригов, переходов и 3D. Для установки README просит Node.js 24 или новее, Google Chrome или Chromium и ffmpeg с ffprobe в PATH. Python 3 нужен только вспомогательным скриптам скиллов, Blender — основному 3D-пути скилла ассетов, оба необязательны. Команды из README: npm install -g @motlab/cli и npx @motlab/cli setup. Setup по умолчанию копирует скиллы в Claude Code; для Codex, Cursor, OpenCode, GitHub Copilot, Gemini CLI, Amp, Windsurf и Muse Code README указывает --skill agents, для Antigravity — --skill antigravity, для Hermes Agent — --skill hermes, для другого агента — --skill-dir. Пример открывается командой motlab edit example, адрес просмотрщика в README — http://127.0.0.1:4173/p/example/. Рендер из терминала: motlab render example --scale 1. Сцену можно написать руками, без агента: это обычная HTML-страница. В разделе Speed README публикует замер одной сцены на одном ноутбуке и прямо пишет, что macOS не замеряли, а машина совсем без GPU не проверялась. Этот выпуск тот прогон не повторял. Статус в README: проект молодой, основная сборка и замеры — один ноутбук с Windows. Лицензия MIT. Переходы сцен README относит к gl-transitions (MIT) и отсылает к THIRD_PARTY_NOTICES.md. Файлы, которые приносят в проект, сохраняют свои лицензии.

Кому: тем, кто собирает ролик из своих референсов кодом сцены, а не моделью видео, и хочет смотреть кадры локально до экспорта. На что обратить внимание: Node.js 24, Chrome или Chromium и ffmpeg; скиллы setup кладёт в папку агента. Цифры скорости — из README, не из этого выпуска. Отдельной домашней страницы в снимке API нет. lg-debloat: лишнее на LG webOS

ChrisTitusTech/lg-debloat в описании GitHub — «Debloat LG WebOS 2+ TVs». README формулирует задачу уже: уменьшить промо LG и лишнюю фоновую активность на рутованном телевизоре LG webOS и оставить Plex, YouTube, Developer Mode, Homebrew и входы телевизора. Скрипт прячет выбранные встроенные приложения, выключает поддерживаемые настройки промо и не даёт выбранным приложениям загружаться заранее. Запись изменений README хранит локально, чтобы откатить. Приложения скрипт не удаляет и рекламу внутри YouTube, Plex и других стримингов не режет. До старта README требует рутованный телевизор с рабочим root по SSH, Python 3.9 или новее и OpenSSH на компьютере. Одного Developer Mode README считает недостаточным. Поддержка зависит от модели. Планирование только на чтение README относит к проверенному на webOS 4.x. Применение и откат покрыты автоматическими тестами, но на живом телевизоре этим новым скриптом, по тексту README, ещё не проверялись. Быстрый старт скачивает lg-debloat.py из последнего релиза и сначала вызывает python3 lg-debloat.py plan --host tv: эта команда настройки телевизора не меняет. tv в README — IP или SSH-алиас. SSH должен уже доверять ключу хоста и входить ключом без запроса пароля. Применение по умолчанию — python3 lg-debloat.py apply --host tv, статус — status, откат — restore. Файл private/universal-state.json README просит хранить: в нём исходные настройки этого прогона. Делиться им README не советует. Более жёсткий профиль смотрят заранее: plan --host tv --profile minimal, и тот же флаг передают в apply. Отдельные инструкции README описывает как необязательные и зависящие от модели: скрипт сам не ставит свой домашний экран и не выключает AirPlay. Лицензия MIT.

Кому: тем, у кого уже есть root по SSH на своём LG webOS и кто хочет сначала прочитать план, а потом решать, применять ли его. На что обратить внимание: Developer Mode сам по себе README не считает доступом. Команда plan ничего не пишет на телевизор, apply пишет. Файл состояния нужен для отката, и README просит его не публиковать. Creator Studio Document Format: Keynote без Keynote

apple/creator-studio-doc-format в описании GitHub — «A Python library for reading, creating, and editing Apple Creator Studio documents, starting with Keynote.» README работает с презентациями Keynote в Keynote Interchange Format, файлы .keyx. Библиотека читает слайды, текст, картинки, таблицы, графики и стили из .keyx, экспортированного из Keynote; собирает презентацию с нуля или из макетов и стилей темы; правит её и сверяет с правилами формата перед сохранением. Читает и пишет .keyx сама: Keynote, устройство Apple и сеть для этого README не требует. Посмотреть результат README предлагает в Keynote на устройстве Apple. В другие форматы, например PDF, README отсылает к Creator Studio Document Exporting API. Установка: Python 3.13 или новее и pip install creator-studio-doc-format. Короткий пример собирает Presentation со слайдом и текстовым блоком, оборачивает в KeyxDocument и сохраняет hello.keyx. Документация README разложена на три части: руководство, справочник API и примеры. Сайт из снимка API — apple.github.io/creator-studio-doc-format, туда README ставит руководство и справочник. Скилл creator-studio-doc-format учит агента пользоваться библиотекой. README ставит его из последнего релиза командой gh skill install apple/creator-studio-doc-format creator-studio-doc-format и пишет, что релиз совпадает с последней библиотекой на PyPI. Агент, который читает папки SKILL.md, может взять копию папки скилла из репозитория. Скиллу нужна установленная библиотека. Issues открыты для отчётов и запросов. Код и документацию в репозиторий, по тексту README, сейчас не принимают. Лицензия в снимке API — Apache-2.0. README относит проект и файлы репозитория к Apache License 2.0, если не оговорено иное.
