gpucanvas: живые экраны на холсте, агент указывает

berkantay/gpucanvas в описании GitHub кладёт тысячи живых DOM-узлов на бесконечный холст. GPU их рисует, редактор выбирает, двигает и меняет размер, на узлах работают шейдеры и переходы, а ИИ-агент может прочитать холст и указать на элемент. Демо README открывает в Chrome 157 и новее: berkantay.github.io/gpucanvas. Статус в README — ранняя версия 0.4, API ещё может измениться. Установка пакета: npm install gpucanvas. Узлы остаются настоящим DOM: состояние React, события, CSS и доступность работают как обычно. Где есть WebGPU и HTML-in-Canvas, узлы попадают в атлас и рисуются одним instanced-вызовом. Иначе тот же API рисует запасной путь через CSS-transform.

Редактор подключается через bindEditor: клик выбирает слой, двойной клик спускается глубже, перетаскивание двигает с привязкой к соседям. Встроенные эффекты README перечисляет по именам: glass, frost, shockwave, glitch, vhs и другие, свой эффект — функция WGSL. Вид для агента, createAgentView, отдаёт то, что в кадре, коротким JSON с id, ролью и прямоугольником, и умеет снять регион в картинку. Снимок региона README относит к GPU-пути. Пометки — стрелки, булавки, заметки и курсоры — лежат слоем SVG и HTML и работают на обоих путях отрисовки. В README есть таблица замера версии 0.1: Mac на чипе M, Chrome 157, окно 1600×900, DPR 1, 5 000 экранов, средний fps 117 у gpucanvas и 23 у DOM-пути. Этот выпуск демо и замер не запускал.

Haru: слушает и говорит в одном кадре

higurashi-ai/Haru в описании GitHub — речевая модель с малой задержкой, несколькими языками и полным дуплексом: слушает и говорит одновременно, как в телефонном разговоре. В репозитории код инференса Haru-4B, предобученной базовой модели. Три реализации читают один чекпоинт higurashi-ai/Haru-4B: PyTorch в haru/, MLX для Apple silicon в haru_mlx/ и плагин vLLM-Omni в haru_vllm/. Каждые 133 мс модель принимает один кадр звука пользователя и выдаёт свой кадр звука и текста. README перечисляет языки: английский, испанский, португальский, немецкий, французский, китайский, японский, русский и корейский. Характер задаёт текстовая карточка, голос — короткий референс.

Быстрый старт README для NVIDIA, около 12 ГБ памяти: pip install -e ./haru и python -m haru.server --hf-repo higurashi-ai/Haru-4B, затем страница http://localhost:8998. Микрофон браузер отдаёт странице на localhost или по HTTPS. Голосовых клипов в поставке нет: свой клип, один говорящий, от 3 секунд до 3 минут. README просит использовать только голоса, на которые есть право. Для малой задержки README рекомендует проводные наушники и проводной микрофон: Bluetooth, по тексту README, добавляет 100 мс и больше. На Mac с Apple silicon README собирает нативное приложение из haru_mlx/swift. Ограничение README прямое: Haru-4B — базовая модель для исследований. Разговор она держит, источником фактов README её не называет и следование инструкциям как у ассистента не обещает. Лицензия кода и весов в README — Apache License 2.0.

Кому: тем, кто смотрит полный дуплекс речи с кадром 133 мс и отдельными путями под NVIDIA, Apple silicon и vLLM, и кто читает ограничение про исследовательскую базовую модель до того, как звать её ассистентом. На что смотреть: язык по API — Python, лицензия Apache-2.0, 227 звёзд, push 13.11.2026, 09:21:17 МСК. Репозиторий создан 12.11.2026, 14:15:42 МСК. На момент снимка он не был архивным. islandcn: остров статуса в React

opencoredev/islandcn в описании GitHub — Dynamic Island с открытым кодом для React, установка через shadcn. Сайт — islandcn.dev. Команда из README: npx shadcn@latest add https://islandcn.dev/r/island-core.json. Один остров наверху приложения показывает загрузку, таймер, трек, поездку, входящий звонок или запись. Активность стартует из любого компонента внутри IslandProvider через useIsland(): у активности есть компактный и развёрнутый вид, её можно обновить и завершить.

Движок README кладёт в lib/island/: стек активностей, четыре показа (idle, compact, split, expanded), пружины, подобранные по покадровым записям настоящего острова, долгое нажатие, алерты и reduced motion. Движок — только React. Пресеты лежат отдельно, каждый одним файлом: загрузка, таймер, «сейчас играет», звонок, ETA поездки или доставки, запись, передача рядом, батарея и split. Площадка /playground собирает остров из пресета или пустой активности и копирует команду установки. Для кодинг-агентов README указывает необязательный пункт реестра islandcn-skill, описание на /docs/agent-skill. Записи, по которым подогнали движение, в репозиторий не входят: /compare в README сравнивать не с чем, тест, который их читает, пропускается. Лицензия MIT. relax: Rust без ожидания полной сборки

makepad/relax в описании GitHub — Relax Rust JIT. README точнее: живой компилятор и JIT-рантайм для Rust, написанный на Rust. Программа запускается из исходников пакета Cargo. В цикле нет rustc, LLVM и линкера: функция компилируется при первом вызове, горячие функции оптимизируются, пока программа идёт, правка вшивается в уже запущенный процесс. Предупреждение README в начале файла: это эксперимент для цикла разработки — запуск, тесты и правка на живую. То, что уходит в релиз, README предлагает собирать самим Rust: cargo build --release и rustc. Пока, пишет README, проверку вели в основном в цикле правки Makepad и лишь слегка на других проектах.

Сборка из свежего клона в README: cargo build --release --manifest-path relax/Cargo.toml -p relax-runner --bin relax, затем relax run, relax test и relax check по имени пакета. Самому бинарнику README достаточно стабильного Rust и ничего с crates.io. Кодогенерация — x86-64 и AArch64. README пишет, что со свежего клона репозиторий собирается и тесты проходят на Linux x86-64 и macOS arm64. Windows README не проверял. Тело функции патчится на живую. Смена раскладки структуры, импорта, заголовка трейта или impl, а также макроса ждёт перезапуска: relax inspect <pid> session relaunch. Открытые пробелы README собирает в libs/relax/KNOWN_GAPS.md. В таблице README большой 3D-игре со свежего состояния до первого кадра отведено около 3 минут сборки у cargo и rustc и 11 секунд у Relax на MacBook M4. Там же скорость уже оптимизированного кода: в среднем по 21 нагрузке Relax медленнее rustc --release, 1,12× по времени на x64 и 1,24× на arm64, замер README датирует 2026-11-12. Этот выпуск эти цифры не повторял.

Кому: тем, кто крутит цикл правки Rust и хочет компилировать вызванную функцию, а не весь крейт заранее, и кто читает предупреждение про экспериментальный статус до того, как заменить этой сборкой релизный cargo build --release.
