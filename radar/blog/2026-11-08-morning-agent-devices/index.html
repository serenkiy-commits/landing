Mika: агент на Android, который работает с приложениями и сайтами

wangzan101/Mika в описании репозитория — on-device AI-агент для Android: он управляет приложениями и вебом, чтобы сделать задачу. README говорит то же своими словами: ассистент на телефоне выполняет просьбу в приложениях и на сайте, пока она не закрыта, и делает это на отдельном фоновом экране, чтобы основным экраном можно было пользоваться. Кнопки он ищет по экрану, без API конкретного приложения. Своего сервера у Mika нет: нужен свой ключ модели или вход в аккаунт ChatGPT, xAI или OpenRouter. Для чата, веба и файлов README указывает Android 11 и новее; чтобы управлять приложениями телефона — Android 12 и новее, Android 14 и новее назван рекомендуемым. Отдельно README описывает Linux-песочницу на разговор для Python, Node и shell, на устройствах arm64. Лицензия Apache-2.0, основной язык Kotlin, 7620 звёзд, push 7 ноября 2026.

Смотреть тем, кому нужен агент на своём Android. Оговорки из README: автоматическое управление чужими приложениями и сайтами может нарушать их условия; по умолчанию режим Ask спрашивает человека перед тратой денег. Чтобы управлять приложениями, один раз нужно связать wireless debugging. Своего сервера нет, но текст и содержимое экрана уходят к выбранному провайдеру модели. Этот выпуск приложение не устанавливал.

Poki: локальный агент для настоящего iPhone

JosssphZhou/poki в описании репозитория даёт AI-агентам управлять настоящим iPhone: локальные MCP-сервер и агент, без jailbreak и без дополнительного железа. README целится в macOS. Для сборки из исходников там названы macOS 15 или новее, полный Xcode, Rust, Node.js 24+ и ffmpeg; есть отдельный готовый пакет под macOS arm64. MCP подключается к Claude Code, Codex и другим клиентам с mcpServers. Отдельный Poki Agent запускается в терминале: README называет модель по умолчанию GPT-6.1 Terra (gpt-6.1-terra) и переменную POKI_AGENT_MODEL, чтобы её сменить. Физический iPhone README просит сначала связать с Mac по USB. Сайт: poki.bot. Лицензия AGPL-3.0, в README бейдж указан как AGPL-3.0-only. JavaScript, 520 звёзд, push 8 ноября 2026.

Это вариант для тех, у кого уже есть Mac и iPhone и агент должен нажимать по настоящему телефону. Оговорки из README: если попросить отправить сообщение или провести оплату, Poki это сделает; содержимое экрана уходит в настроенный сервис модели. Поддержка физического iPhone там проверена только на устройствах с китайским интерфейсом и только в портретной ориентации. Сам репозиторий целится в macOS; порты на Linux и Windows README указывает как сторонние и ведёт вне этого репозитория, а Windows-порт — как не проверенный авторами. AGPL-3.0 стоит учесть до коммерческого использования: условия другие, чем у MIT и Apache-2.0 остальных трёх репозиториев выпуска.

devvm: отдельная виртуальная машина на каждый проект

devvmhq/devvm — одна виртуальная машина на проект: изолированная песочница с инструментами этого проекта, чтобы начать писать код самому или отдать это coding-агенту. README ставит требование macOS 13 или новее либо Linux, архитектуры arm64 или x86_64, и Lima 2.2 или новее. По тексту README проект проверен на Apple silicon и на Linux arm64 и x86_64, на Intel Mac — ещё нет. Тулчейны node, python, rust, go и dotnet определяются по файлам проекта. Внутри машины README называет Claude Code, Codex, opencode и pi; их настройки и входы devvm хранит у себя, агент ставится в машину, а не на хост. Бэкенд — Lima. Машина по умолчанию монтирует только папку проекта и получает сетевой уровень allowlist: наружу только разрешённые хосты. Секреты вроде токена GitHub и токена Claude Code README оставляет на своей машине. Документация: devvm.dev/docs. Лицензия MIT, Go, 366 звёзд, push 8 ноября 2026.

Подходит, когда coding-агент должен работать в песочнице проекта, а не на основной системе. Оговорка прямо в README: ни одна песочница не закрывает все зазоры, перед тем как доверить машине проект, стоит прочитать раздел Staying safe. Флаг devvm --clone в README даёт машине собственный клон репозитория, чтобы она не трогала рабочее дерево и .git.

sandbox-mcp: одноразовый Windows Sandbox для проверки приложений

shanselman/sandbox-mcp — MCP-сервер и CLI, которые автоматизируют Windows Sandbox: свежая одноразовая машина Windows, чтобы проверить своё приложение. README описывает настоящий одноразовый рабочий стол Windows 11, не контейнер. Команда sbx работает сама; MCP — необязательный адаптер к тому же движку, для клиентов, которым нужны схемы инструментов и снимки экрана. Windows Sandbox, по README, есть в выпусках Pro, Enterprise и Education и недоступен в Home и на Windows Server. Нужна вошедшая в систему сессия Windows на хосте: Sandbox — функция рабочего стола. Сеть гостя можно выключить. Каждый запуск, по README, начинается с чистой машины; среды выполнения сами не ставятся, пока это явно не запрошено. Сайт: shanselman.github.io/sandbox-mcp. Лицензия MIT, JavaScript, 277 звёзд, push 7 ноября 2026.

Смотреть тем, кто проверяет Windows-приложение на чистой машине или хочет, чтобы агент не трогал основной рабочий стол. Оговорки из раздела Limits в README: одновременно может работать только один Sandbox, это правило Windows Sandbox, и второй запуск не встаёт в очередь, а сразу завершается с ошибкой. Внутри нет приложений Microsoft Store, winget, Блокнота, Калькулятора и Windows Terminal. README не обещает, что в Sandbox заведётся любое приложение или нагрузка, которой нужно особое железо. Замеры времени из README в этом выпуске не повторялись.
