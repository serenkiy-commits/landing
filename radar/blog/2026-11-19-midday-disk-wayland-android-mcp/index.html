Roomy: место на диске Windows

krezio/roomy в описании GitHub — «Your C: drive is full. Let's fix that. See what's eating your space in plain English and clean the safe stuff in one click.» README повторяет ту же формулу: увидеть, что занимает место, простыми словами и почистить безопасное в один клик. Сайт — roomy.krezio.xyz. README относит программу к Windows 10 версии 2004 и новее и к Windows 11. Сборка из исходников требует .NET 10 SDK. К категории Safe по умолчанию README относит остатки Windows Update, Delivery Optimization и временные файлы Windows (для них нужны права администратора); кэши Discord, Spotify, VS Code, Slack, Teams, npm, pip, Yarn, NuGet и лаунчеров Steam, Epic, Battle.net, EA app, Ubisoft Connect, Riot Client и GOG Galaxy; кэши Chrome, Edge, Brave, Vivaldi, Firefox и Opera; временные файлы старше суток, дампы сбоев, отчёты об ошибках и корзину. Кэши шейдеров GPU (NVIDIA, AMD, Intel, DirectX, Steam) README помечает как безопасные, но снятые с галочки. На усмотрение пользователя: старые установщики и большие нетронутые загрузки, игры Steam, в которые не играли два месяца и дольше (удаление через Steam), Windows.old через штатную очистку Windows и файл гибернации. Про файл гибернации README пишет, что он часто занимает 6–16 ГБ; выпуск это не замерял. Отдельно есть карта места: папки диска и самые большие файлы. Сканирование README описывает как только чтение: удаление начинается после Clean up. Папки Documents, Desktop, Pictures, Videos, Music, Downloads как папка, папка пользователя, Windows и Program Files заблокированы. Junctions и symlinks программа не следует, занятые файлы пропускает. Сети README не заявляет: ни телеметрии, ни аккаунтов, ни обновлений «домой»; при сбое текст ошибки пишется в %LOCALAPPDATA%\Roomy\crash.log на этом компьютере. По умолчанию файлы удаляются насовсем, и программа говорит об этом до подтверждения. Фоновые проверки README описывает как выключенные: трей, автозапуск, проверка свободного места на системном диске каждые 30 или 60 минут (порог от 1 до 500 ГБ, по умолчанию 10 ГБ) и еженедельная проверка кэшей. Сами проверки ничего не удаляют. Интерфейс следует языку Windows: английский, русский и упрощённый китайский. Установка из README: Microsoft Store, Roomy-Setup.exe на пользователя без прав администратора или Roomy-portable.exe из релизов.

Кому: тем, у кого на Windows заканчивается место и кто хочет сначала прочитать, что занимает диск и что README считает безопасным. На что обратить внимание: репозиторий создан 12.11.2026. Без перезапуска от администратора категория остатков Windows пропускается. Язык по снимку API — C#, лицензия MIT. 463 звезды на 19.11.2026, ~11:20 МСК, последний push 19.11.2026. MATE Wayland Desktop: MATE на Wayland

scottsturrock/mate-wayland-desktop в описании GitHub — «MATE Wayland Desktop: the MATE desktop on Wayland with labwc, on an Ubuntu 26.04 base. Sources and build system.» README описывает дистрибутив вокруг двухпанельного рабочего стола MATE, продолжения GNOME 2, на Wayland. Панель, меню, файловый менеджер и настройки MATE работают на композиторе labwc вместо оконного менеджера MATE, который README называет только для X11. Исходники — весь проект: сессия, настройки, сборка пакетов, оформление и система, которая собирает live ISO. README пишет, что проект независимый и не связан с проектами MATE и GNOME и с Canonical; база — Ubuntu. Сайт — mate-wayland.org, ISO, контрольная сумма и шаги установки — mate-wayland.org/download/. В поставке README называет меню Applications, Places и System, область уведомлений, батарею, громкость и часы сверху, список окон и переключатель рабочих столов снизу, значки на рабочем столе, файловый менеджер Caja, MATE Control Center и Firefox с uBlock Origin. Тема Menta, шрифт Noto Sans, значки Yaru, свои обои, логотип, экран входа, блокировка и заставка загрузки. Несколько мониторов, у каждого своё разрешение. Live ISO для USB или DVD (UEFI), установщик Calamares, необязательное шифрование LUKS2; /boot остаётся незашифрованным, как у установщика Ubuntu. Таблица README: пакеты Ubuntu 26.04 LTS, Linux 7.0, без GNOME Shell и без snap; Wayland и labwc 0.9 (wlroots); XWayland для программ только под X11; MATE 1.29 и mate-applets 1.28; LightDM и Calamares 3.3; Firefox из APT-репозитория Mozilla. Сборка — на машине семейства Debian с debootstrap, apt, sudo, curl и компилятором C. Команды из README: ./build.sh --packages в первый раз, затем ./build.sh. ISO пишется в iso/out/. Первую сборку пустого клона README оценивает примерно в 35 минут, полную пересборку ISO примерно в 8 минут, пересборку после правок только своих файлов примерно в минуту. Эти сроки выпуск не замерял. ISO стартует на открытых драйверах ядра: для NVIDIA это nouveau. Проприетарный драйвер README предлагает ставить после установки системы командой sudo ubuntu-drivers install, нужен интернет.

Кому: тем, кто хочет классический двухпанельный MATE на Wayland и готов взять ISO или собрать его. На что обратить внимание: Ubuntu 26.04 LTS, ядро Linux 7.0, labwc 0.9 и MATE 1.29 — формулировки README на дату снимка. Лицензия проекта GPL-3.0; README пишет, что компоненты из других проектов сохраняют свои лицензии. Репозиторий создан 16.11.2026. Jiumi: поведение приложений Android

ybblab/Jiumi в описании GitHub — «揪咪 Jiumi：开源安卓应用行为监测与管理，查看权限访问和网络活动。Android app activity & privacy monitor. No root required.» README описывает лёгкий инструмент мониторинга и управления поведением приложений Android: компьютер не нужен, записи хранятся на телефоне. Сайт — jiumi.ybblab.com, руководство — jiumi.ybblab.com/download/. README указывает Android 11 и выше и размер установочного пакета около 4 МБ. Журнал смотрят по времени, приложению или типу; среди примеров README — местоположение, буфер обмена и идентификаторы устройства. README называет 12 классов данных и 56 видов доступа и отдельный фильтр фоновых записей. Блок «нужно внимание» собирает отправку данных в фоне, чтение чувствительных данных в фоне, частый доступ за короткое время и повторные отклонённые попытки. По приложениям видны адреса соединений и доступная статистика трафика; после включения записи доменов показываются связанные домены. В карточке приложения README обещает детали доступа к разрешениям, которые хранит сам Android, включая часть поведения до начала мониторинга. Экспорт — ZIP с CSV за выбранный период. Пока мониторинг идёт, висит уведомление с длительностью и кнопкой остановки. Управление README описывает как действия пользователя: разрешения по одному, общий выключатель контролируемых разрешений, заморозка для текущего пользователя с сохранением данных, удаление самостоятельно установленного приложения после ввода полного имени пакета. Перед таким удалением README описывает копию установочного пакета и прямо пишет: данные приложения при удалении пропадают, копия восстанавливает только пакет. На поддерживаемых устройствах сеть одного приложения закрывается штатным файрволом Android, без VPN. Как README объясняет наблюдение без обязательного root: зонд читает сигналы с правами shell — записи AppOps, таблицу соединений (по умолчанию раз в 5 секунд), трассировку Perfetto и журнал событий — и не внедряет код в другие приложения. Запуск зонда: беспроводная отладка, Shizuku или root. Необязательная запись доменов поднимает локальный VPN: DNS-запросы принимаются и без изменений уходят DNS-серверу текущей сети, остальной трафик идёт напрямую, слот VPN системы при этом занят. Записи README обещает не выгружать, аккаунта нет. Проверка обновлений с GitHub отключается; выбранный пакет сверяется по размеру, SHA-256 и подписи. Текст переписки, пароли и тело сетевой передачи README относит к тому, чего инструмент не видит. Статистика трафика по соединениям — Android 14 и выше и поддержка системы. Сборка: JDK 17, Android SDK, из каталога code команда ./gradlew :app:assembleDebug. README просит ставить приложение на своё устройство или на то, где есть разрешение.

Кому: тем, кто на Android 11 и новее хочет смотреть доступ приложений к разрешениям и сетевую активность и держать журнал на телефоне. На что обратить внимание: «без root» в описании GitHub относится к чтению сигналов через shell. Беспроводная отладка, Shizuku или root нужны, чтобы этот зонд запустить. Запись доменов занимает VPN. Nexus: локальный MCP для веб-ассистентов

ysunyang4/Nexus в описании GitHub — «Connect web AI assistants to local files, terminals, Git, and desktop tools through MCP, with user-controlled permissions.» README называет Nexus локальной панелью MCP для совместимых клиентов: разрешённые инструменты отдаются по MCP Streamable HTTP с bearer-токеном. Рядом описано необязательное расширение WebAgent для совместимых веб-чатов; Nexus README предлагает подключать и к другим MCP-клиентам. Бейдж README показывает версию 1.3.1, платформы Windows, macOS и Linux и формулировку «332 Canonical MCP Tools» в 24 возможностях. Выпуск это число не пересчитывал. Схема README: веб-чат ходит на локальный адрес, панель на Tauri 2 поднимает Fastify на порту 18080 и SQLite с WAL, дальше JSON-RPC 2.0 по WebSocket к локальному раннеру. У раннера README перечисляет журнал действий с записью до побочного эффекта, восстановление после сбоя, нативное управление окнами Windows через WinRT OCR и UI Automation, песочницы каталогов, git worktree, LSP для TypeScript и Python и браузерную автоматизацию. По умолчанию README описывает песочницу путей read-only и фильтр команд safe-only. Режимы доступа (read-only или read-write) и исполнения (disabled, safe-only, project-code) переключаются без перезапуска. Если включить запись, исполнение кода проекта, автоматизацию интерфейса или режим полного контроля, README перекладывает ответственность за команды и файлы на пользователя. Маска чувствительных файлов в README: .env*, *.pem, *.key, id_rsa, .git и облачные учётные данные. Результаты, которые возвращаются в веб-чат, могут уйти с машины к стороннему сервису — README просит это учитывать. Подключение: авторизовать каталог, выпустить токен клиента и указать http://127.0.0.1:18080/mcp с заголовком Authorization: Bearer. Сборка из README: Node.js 24 или новее, pnpm 10 или новее, стабильный Rust, затем pnpm install, pnpm run build и pnpm --filter @localbridge/desktop dev. Про установщик README предупреждает: скачивать только файл, который реально лежит в Assets релиза, и не предполагать сборку под свою систему, пока её нет на странице; сборки тега v1.3.1 и ветки main могут различаться. Лицензия в снимке API — AGPL-3.0. README относит её к GNU AGPL-3.0 и отсылает к тексту лицензии, в том числе к обязанностям при распространении и при сетевом доступе к изменённой версии.

Кому: тем, кто хочет сам решить, какой локальный каталог и какой режим открыть веб-ассистенту или другому MCP-клиенту. На что обратить внимание: AGPL-3.0, ответы инструментов уходят в подключённый чат, а полный контроль README описывает как ответственность пользователя. Репозиторий создан 13.11.2026.
