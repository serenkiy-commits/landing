tvpipe: зеркало на AirPlay и Google Cast

mitsuhiko/tvpipe в описании GitHub — «Airplay/Chrome Cast anything». README описывает CLI для низкозадержечного зеркалирования видео и звука на приёмники AirPlay и Google Cast: Apple TV, смарт-ТВ, Chromecast и Google TV, а также на вкладки браузера. Картинка и звук идут протоколами real-time mirroring. README отделяет этот путь от воспроизведения файла по URL.

Кому: тем, кто хочет вывести файл, экран, окно или вкладку на Apple TV, смарт-ТВ, Chromecast, Google TV или вкладку браузера. Как попробовать по README: tvpipe discover ищет приёмники, pair нужен только для Apple TV, play --to <TV> file.mp4 отправляет файл и одним кодированием может идти на два ТВ, screen зеркалирует экран со звуком или одно окно через --window, share отдаёт вкладку браузера или веб-страницу, game play запускает party-игру на ТВ и телефонах. Установка: install.sh для macOS и Linux, install.ps1 для Windows. Для файлов и URL нужны ffmpeg и ffprobe. Node SDK ставится командой npm install @tvpipe/sdk. Сайт и мануал: mitsuhiko.github.io/tvpipe — тот же адрес стоит домашней страницей в снимке API. Orchard: self-hosted PaaS от Hack Club

hackclub/orchard в описании GitHub — open-source self-hosted платформа деплоя: из Git на свой сервер одной командой. README называет её PaaS от Hack Club, проект Leafd. К платформе подключают репозиторий из GitHub, GitLab, Gitea или другого Git-хоста. Orchard собирает его и запускает по HTTPS. В комплекте Postgres с point-in-time restore из S3-совместимого хранилища, логи, метрики и откаты. Управление — дашборд, CLI или AI-агент через MCP-сервер. Платформа работает на Kubernetes. Одна команда, по README, превращает один Linux-сервер в k3s-кластер: README указывает домашнюю лабораторию, сайд-проект и малую команду. Для продакшена README даёт Helm chart на мультинодовом кластере, пример — Talos Linux. Hack Club сам запускает Orchard на шести нодах Talos Linux. Лицензия в README и в снимке API — AGPL-3.0.

Кому: тем, кто хочет self-hosted PaaS на своём сервере и деплой из Git, с логами, метриками, откатами и Postgres. Как попробовать по README: документация на docs.orchard.hackclub.com. Pulsar: агенты видят друг друга

yocontra/pulsar в описании GitHub даёт агентам находить друг друга и свободно переписываться между харнессами и между машинами, а также управлять ими с любого устройства. README описывает MCP-сервер и маленький демон на каждую машину. Любой кодинг-агент из списка README — Claude Code, Codex, OpenCode, pi, omp, Cursor, Gemini CLI или любой MCP-клиент — видит, кто ещё запущен, помечает себя тегом и пишет одному агенту, группе или всем. В большинстве харнессов сообщение будит простаивающего агента. Agent mesh работает между машинами в сети Tailscale. Приложение Pulsar показывает агентов и даёт управлять ими с телефона или другого компьютера. Отдельного сервера Pulsar и аккаунта README не требует.

Кому: тем, кто держит несколько кодинг-агентов и хочет, чтобы они видели друг друга и обменивались сообщениями, в том числе между машинами в Tailscale. Как попробовать по README: npx pulsar setup. Команда показывает, какие файлы изменит, спрашивает один раз и делает бэкап каждого изменяемого файла. Домашняя страница в снимке API — npmjs.com/package/pulsar. Pansy: локальный шлюз моделей для агентов

pansy-ai/pansy в описании GitHub — локальный шлюз, через который каждый кодинг-агент получает модели любого провайдера, плюс десктоп-окно. README описывает локальный шлюз и десктоп-приложение для Linux, macOS и Windows на Rust. Окно собрано на Native Shell (NSH). Модель выбирается для агента из списка README: Claude Code, Codex, Gemini CLI, OpenCode, Qwen Code, Crush и ещё около пятидесяти агентов. Приложение меняет одну нужную настройку в конфиге агента. Disconnect возвращает ровно то, что изменил. Шлюз слушает 127.0.0.1:7267 и говорит на Anthropic Messages, OpenAI Chat Completions, OpenAI Responses и Gemini, переводя между этими форматами: стриминг, tool calls и reasoning. У провайдера может быть несколько ключей: при rate limit или исчерпании квоты шлюз переключается на следующий. README пишет, что всё работает локально: ключи, промпты и ответы уходят только выбранным провайдерам.

Кому: тем, кто хочет одну локальную точку для моделей разных провайдеров и подключать её к Claude Code, Codex, Gemini CLI, OpenCode, Qwen Code, Crush и другим агентам из README. Как попробовать по README: сайт pansyai.dev — он же домашняя страница в снимке API. Адрес шлюза из README — 127.0.0.1:7267.
