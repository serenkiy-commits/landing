diego3g/craft в описании GitHub — дизайн-скиллы для ИИ-агентов. /craft-setup пишет дизайн-бриф, /craft собирает экраны со всеми состояниями из дизайн-системы и проверяет их. Агент останавливается на «yes» там, где это важно, и записывает решения на следующий раз.

Скиллы по таблице README. craft-setup задаёт вопросы по одному: продукт, аудитория и голос, настроение, бренд, референсы, ограничения, затем пишет DESIGN.md и основы — токены и базовые компоненты. craft проектирует страницу, экран, поток или элемент: подтверждает объём, для каждого экрана перечисляет состояния, рисует кусками системы и проверяет результат. craft-states перечисляет состояния экрана (empty, loading, error, длинный контент, права, offline и другие) на реалистичных неаккуратных данных, затем рисует и называет каждое. craft-explore рисует три направления, которые отличаются структурой, взаимодействием или плотностью, а не только цветом; они стоят рядом с текущим дизайном, рекомендация — первой. craft-system ведёт систему: токены с именами ролей, правила взаимодействия, заданные один раз, матрица состояний на компонент и индекс компонентов; перед тем как правка разойдётся, перечисляет затронутые экраны. craft-sync переносит систему, которая уже живёт в коде, в инструмент дизайна, а позже отправляет изменения гайда обратно в код как просмотренный diff. craft-critique смотрит на отрисованный дизайн: иерархия, отступы, контраст, текст, согласованность и движение; находки ранжируются по влиянию; в режиме review ничего не меняет. Скрытый скилл using-craft отправляет запрос нужному скиллу. Агенты со слэш-командами вызывают их по имени: /craft, /craft-setup; в плагине Claude Code — /craft:craft, /craft:craft-setup. zim-mcp: офлайн-Википедия для локального агента

gordonbrander/zim-mcp в описании GitHub — локальная Википедия для локального агента и доступ к zim-архивам Kiwix по MCP. README описывает чтение и поиск zim-файлов, офлайн-формата архивов Kiwix: Wikipedia, Stack Overflow, Project Gutenberg и каталог Kiwix. Сервер отдаёт архивы по MCP (stdio) с полнотекстовым поиском, ведёт библиотеку (поиск, просмотр и скачивание каталога) и экспортирует статьи в Markdown. README пишет, что сервер работает с любым ИИ, у которого есть MCP, включая локальные, и называет Llamafile.

Кому: тому, кто хочет дать локальному агенту офлайн-архив, в том числе Википедию, без обращения к сайту энциклопедии в момент вопроса. Как попробовать по README. С GitHub Releases берётся архив под свою ОС: один самодостаточный бинарник zim-mcp. Либо сборка cargo install zim-mcp — чистый Rust, системные библиотеки README не требует. ZIM читает zimfile, порт libzim Kiwix на чистом Rust (чтение и запись) в этом репозитории. Поиск идёт через zimfile-xapian, переписывание поисковых индексов Xapian из libzim. Команды библиотеки: zim-mcp library search wikipedia --lang eng, library add wikipedia_en_all_nopic --dir ~/zim, library list, library update, library remove, library status. Загрузка продолжается после обрыва, сверяется с sha256, который публикует Kiwix, и появляется в папке как <name>_<YYYY-MM>.zim только после проверки. При обновлении старые файлы уходят, когда новые прошли проверку. Папка и есть библиотека: ZIM можно положить вручную. Индекс Xapian архив несёт сам, отдельного шага сборки нет. Редкий архив без индекса ищется только по заголовку: list_archives пишет «titles only». Инструменты MCP: search, read, list_archives, плюс library_search, library_list, library_status, а также library_add, library_update, library_remove и export. Изменения библиотеки и экспорт спрашивают подтверждение. Флаг --no-library прячет инструменты библиотеки и export: README пишет, что маленьким моделям так проще. Для Claude Code: claude mcp add --scope user wiki -- zim-mcp serve --dir ~/zim --dir .. Флаг --dir повторяется: архивы читаются из каждой папки, а add, update и remove идут в первую. Для Claude Desktop, LM Studio и Jan README даёт блок mcpServers в конфиге приложения. Для Pi и агентов, которым ближе CLI, те же операции идут командами search, read и list и печатают Markdown или JSON с --json. Для llama.cpp и llamafile README даёт аргумент --mcp-servers-json с serve, --dir и --no-library. По MCP добавление, обновление, удаление архива и экспорт статей спрашивают человека через elicitation: архив, размер и то, что будет удалено. Модель подтвердить это не может.
