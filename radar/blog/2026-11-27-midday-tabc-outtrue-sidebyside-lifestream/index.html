tabc: контейнер во вкладке

fzakaria/tabc в описании API — OCI-рантайм, который запускает каждый контейнер во вкладке браузера. README ставит его рядом с runc: runc стартует контейнер как процесс Linux, tabc поднимает headless Chromium и загружает контейнер внутри вкладки, на ядре Linux, собранном в WebAssembly. Вкладка и есть песочница. Пример README: docker run --rm --runtime tabc --platform linux/arm64 alpine uname -sm печатает Linux aarch64. README пишет, что Linux под tabc не нужен, поэтому на Mac контейнер идёт без виртуальной машины. Флаг --open открывает контейнер во вкладке уже стоящего браузера: то, что набрано во вкладке и в терминале, видно в обоих местах. Пример: tabc run -it --open -p 8123:80 nginx:alpine sh. Compose README проводит через tocker — тот же файл, что и tabc, под другим именем, замена команды docker. tocker compose up поднимает каждый сервис в своей вкладке. tocker --dashboard compose up собирает сервисы панелями на одной странице, tocker --stop останавливает демон и его контейнеры. В examples/compose — веб-сервер и Redis, в котором тот считает визиты. Установка README даёт двумя путями. С Nix, на Linux или Mac с Apple Silicon: nix run github:fzakaria/tabc -- run alpine echo hi. Без Nix — архив релиза для Linux и для Mac, x86-64 и arm64. tabc из релиза берёт установленные Chrome или Chromium, tocker — установленную командную строку docker. На Linux пакет Nix приносит свой Chromium. На Mac tabc ищет Chrome в /Applications или берёт путь из TABC_CHROMIUM. С --open контейнер идёт в браузере, который уже открыт. Флаги README совпадают с привычными у docker run: -i и -t, -e, -w, -u, -m, --cpus (по умолчанию 2), -p host:container (порт на loopback по умолчанию), -v dir:/path[:ro] (каталог живой и доступный на запись), --name и --network, --open и --link. Свой демон Docker для отдельного запуска README не требует: docker здесь клиент, tocker поднимает минимальный демон, если его ещё нет, и направляет клиент на него, так что команды docker, включая Compose, README описывает как неизменные. Если Docker уже стоит, tabc регистрируется как runtime в /etc/docker/daemon.json, после перезапуска демона контейнер идёт с --runtime tabc. На NixOS README сводит регистрацию к строке virtualisation.docker.daemon.settings.runtimes.tabc.path. docker exec README называет работающим у контейнера, запущенного так. В Compose runtime — строка у сервиса, не флаг docker compose up, и рядом в примере стоит platform: linux/arm64. README пишет, что сети Docker, -p и тома тогда работают как с runc. Podman README запускает без отдельной регистрации: podman run --rm --runtime /path/to/tabc --platform linux/arm64 alpine echo hi. Ход README раскладывает так. Движок, Docker или Podman, вызывает tabc create, как вызвал бы runc. Супервизор стартует headless Chromium со свежим профилем на странице, которую отдаёт с loopback. Страница загружает unkernel — ядро Linux для WebAssembly авторства Pooya Parsa; оно исполняет программы aarch64. Гость монтирует образ, каждый открытый файл — запрос супервизору, который читает его из бандла или прямо из слоёв, поэтому образ не распаковывается. tabc start запускает программу. Ввод, вывод и каждое сетевое соединение идут по WebSocket к супервизору; входящие соединения супервизор слушает на портах, которые открыла программа, и несёт их во вкладку. Движок считает контейнером супервизор и берёт у него pid, код выхода и stdio. Подробности README отсылает в docs/design.md. Лицензия tabc — MIT. Ядро unkernel README помечает GPL-2.0. Язык в снимке — Go. Смотреть тем, кто хочет гонять OCI-образы во вкладке, в том числе на Mac без виртуальной машины Linux, или подставить tabc вместо runc в Docker и Podman. Перед запуском сверить две лицензии: MIT у tabc и GPL-2.0 у ядра unkernel. Примеры Docker и Podman в README идут с платформой linux/arm64. outtrue: правила Oxlint для дизайн-системы

jakubkrehel/outtrue в описании API — правила Oxlint, которые держат код на дизайн-системе: токены, пропсы, импорты и композицию. README добавляет: каждая ошибка называет исправление, чтобы агент и человек правили её в том же прогоне. Правила читают имена классов Tailwind в коде React и требуют Oxlint 1.92 или новее. Установка: npm i -D oxlint outtrue. В конфиге README подключает ./node_modules/outtrue/configs/recommended.json и задаёт settings.design-system.primitives — папку своих примитивов, в примере src/components/ui. По умолчанию это src/design-system/components. Папка, которой нет, сообщается как ошибка. Конфигов три: base включает три стартовых правила, recommended добавляет ещё двенадцать, all включает все двадцать четыре. Среди имён в README: no-raw-values — жёстко заданные длины и цвета в классах, атрибутах и inline-стилях; layout-only-classname — className, который перестилизует примитив вместо того, чтобы его разместить; one-way-imports — импорт с уровня выше; no-rebuilt-primitives — сырой <button>, <input> или собранный вручную оверлей там, где примитив уже есть; semantic-tokens-only — сырой класс палитры вроде text-gray-900 вне дизайн-системы; icon-button-label — кнопка только с иконкой без aria-label; no-important — модификатор !; no-inline-style — фиксированное значение в объекте style. Полный список из двадцати четырёх имён лежит в README. У каждого правила есть опции папок, имён и исключений; README отсылает их в OPTIONS.md вместе с тем, как включать правила в коде, который их уже нарушает. Релизы перечислены в CHANGELOG.md. Лицензия MIT, язык в снимке — TypeScript. Смотреть тем, кто уже гоняет Oxlint на React с Tailwind и хочет, чтобы отход от своих примитивов и токенов был ошибкой линтера с названным исправлением. Перед включением проверить версию Oxlint — 1.92 или новее — и путь primitives: несуществующая папка для этих правил ошибка. Side by Side: несколько браузеров во вкладке

michidk/sidebyside в описании API открывает один URL в Firefox, Chromium, Epiphany и других браузерах рядом. Каждый — настоящий браузер в своей Linux VM на WebAssembly во вкладке. Страница статическая, сервера за ней нет. README называет живую страницу michidk.github.io/sidebyside и просит открывать её на настольном компьютере с 8 ГиБ оперативной памяти или больше. По кнопке Open Firefox (Gecko), Chromium (Blink) и Epiphany (WebKit) загружаются каждый в своей панели. Первый визит README оценивает в 1–3 минуты, пока браузеры скачиваются; следующие визиты берут кэш. Меню Browsers добавляет Firefox ESR и NetSurf и задаёт порядок панелей. Mobile переключает окно на размер телефона и, кроме NetSurf, мобильный user agent, без перезагрузки VM: Firefox и Chromium переключаются на ходу, Epiphany перезапускается. Settings задаёт память на VM, показывает CPU, память и сеть панели, выбирает интернет-релей и правит флаги командной строки браузера. Console собирает сообщения веб-консоли Firefox, Firefox ESR и Chromium в один список. Reset забывает сохранённые VM. Новый URL открывается в уже запущенных браузерах: Firefox и Chromium переходят, Epiphany и NetSurf перезапускаются, VM при этом не перезагружается. Ссылка хранит сравнение. README приводит вид ?url=https://example.com/&browsers=netsurf,firefox&mobile=1. Ядро — unkernel, Linux, собранный в WebAssembly и исполняющий программы aarch64, по VM на браузер в своём iframe (vm.html). Каждая VM получает равную долю потоков CPU, не больше 4, в Firefox — 2. Браузеры — сборки nixpkgs. Путь из кэша cache.nixos.org скачивается, когда гость впервые читает файл, и каждый NAR сверяется с NarHash в public/closures/*.json. Скрипт scripts/closures.ts на сборке проверяет подписи narinfo ключом cache.nixos.org. Загрузки лежат в Cache Storage страницы и общие для всех VM. Стартовые флаги выключают обновления, телеметрию, синхронизацию, safe browsing и лишние процессы; они лежат в src/modules/browsers/browsers.ts, правятся в Settings → Browser flags и сохраняются в ссылке. Окна Wayland гостя собирает wland: релей в госте говорит со страницей по vsock. Сырые сокеты страница открыть не может, поэтому TCP гостя идёт по WebSocket на публичный релей Wisp. README называет wisp.mercurywork.shop и anura.pro и пишет, что эти реле видят, к каким хостам подключаются VM. Свой релей задаётся параметром ?wisp=wss://your-relay/. Локальный релей README описывает так: Node.js 18 или новее и команда npx -p @mercuryworkshop/wisp-js wisp-js-server. Процесс слушает только 127.0.0.1:5001 и отказывает соединениям на частные и loopback-адреса, чтобы VM не доставали домашнюю сеть через него. В Settings кнопка «Use local relay» или параметр wisp=ws://127.0.0.1:5001/. После подъёма браузера его VM сохраняется в приватном хранилище сайта: память, процессы и открытая страница. Следующий визит продолжает её, а не грузит Linux заново. Сохранение привязано к браузеру, его флагам, памяти, числу CPU и сборке страницы. В нём остаётся то, что браузер держал в памяти, в том числе cookie показанной страницы. Reset их удаляет. Страница ведёт Chromium по протоколу DevTools и Firefox по WebDriver BiDi. Оба слушают 127.0.0.1:9222 гостя. Сайты в Firefox видят navigator.webdriver равным true, в адресной строке — полосы удалённого управления. VM нужен SharedArrayBuffer, поэтому страницы подключают coi-serviceworker, который добавляет заголовки COOP и COEP там, где хост их не шлёт. Сборка README: bun install, bun run build кладёт статику в dist/client/. Это SPA на TanStack Start: оболочка пререндерится, серверного кода README не описывает. Компоненты — shadcn/ui на Base UI. Отдавать каталог нужно по HTTPS или с localhost, иначе service worker не встанет. Workflow .github/workflows/pages.yml выкладывает каждый push в main на michidk.github.io/sidebyside. Пределы README такие. Первая загрузка занимает 1–3 минуты и скачивает около 800 МиБ на три браузера по умолчанию. VM эмулируются, страницы медленные, Epiphany может показать «Page Unresponsive». Сохранённая VM занимает около 0,3–0,7 ГБ хранилища сайта на браузер: Epiphany 333 МБ, Chromium 513 МБ, Firefox 697 МБ. Возобновлённый Chromium README оценивает примерно в 20 секунд вместо примерно минуты. Вкладке нужно около 2 ГиБ памяти на показанный браузер и 6 ГиБ на три по умолчанию. Ladybird и Servo в VM пока не идут: у Ladybird движок JavaScript резервирует больше адресного пространства, чем есть у гостя, Servo грузит страницы, но не рисует их программным OpenGL. GPU нет, браузеры рисуют программно. Лицензия в снимке API — Apache-2.0. Раздел License в README даёт выбор: Apache License 2.0 или MIT. Язык в снимке — TypeScript.
