exact: одно приложение на web, macOS, iOS и Linux

expo/exact в описании GitHub: приложение пишут один раз, оно идёт нативно на web, macOS, iOS и Linux, а AI-агент может собрать его, запустить, увидеть и протестировать на каждой из платформ. По README это кроссплатформенный runtime. Интерфейс описывают на языке Contract, логику данных — на TypeScript или Rust. Компилятор Contract превращает интерфейс в план. На вебе план становится одним ES-модулем над runtime и настоящим DOM браузера. На macOS, iOS и Linux тот же план исполняет раннер на Rust, раскладку считает ядро по правилам CSS, а рисует сама платформа: AppKit, UIKit или отрисовка на GPU (на Linux в схеме README — vello, запасной путь — tiny-skia). В README сказано, что в UI нет webview и JavaScript-моста и что JavaScript приложения не выполняется до первого кадра. Репозиторий помечен как pre-1.0: стабильности API и обратной совместимости нет, это пересборка более раннего exact.

Агенту в README отведён один скрипт, scripts/agent.mjs, и десять операций, одинаковых на web, macOS, iOS (симулятор или устройство) и Linux: tree, screenshot, tap, type, state, layout, logs, clock, prefer, perf. Между операциями ничего не двигается само: агент сдвигает часы командой вроде clock +60000 или clock settle и читает результат. Тест — файл app.test.contract, один и тот же на любом хосте. Быстрый старт в README записан для macOS на Apple Silicon: Rust через rustup, Bun версии, которую фиксирует package.json (в тексте README — 1.4.2), Google Chrome. Для хостов macOS и iOS указан Xcode 27.1 или новее. Linux в README — для web-цикла и Linux-хоста. TypeScript на нативных хостах требует Hermes: Exact забирает закреплённый бандл Ibex, обычные сборки Cargo после этого идут офлайн.

Кому: тем, кто хочет одно описание интерфейса и прогон агентом на web, macOS, iOS и Linux без отдельного UI на каждой платформе. На что смотреть: scripts/agent.mjs, язык Contract и шов данных (TypeScript на Hermes или Rust). Язык репозитория по API — Rust, лицензия MIT, 2429 звёзд, push 11.11.2026, 11:05:50 МСК. boxery: VM и песочницы для coding-агента

modem-dev/boxery в описании GitHub — способ дать coding-агентам VM: локально, удалённо или облачные песочницы. По README агент остаётся на вашей машине со своим логином и настройками, а работает внутри Linux-VM. Ключи в VM не попадают: машина получает отзываемый токен, хост подставляет настоящий ключ. Пока доступ не выдан, у VM нет даже LLM.

Хост — это Mac, Linux-машина или небольшая VPS. Бэкенды, которые README относит к стабильным: Lima на macOS (Virtualization.framework), libvirt на Linux (QEMU на KVM, нужна физическая машина или вложенная виртуализация) и exe.dev в облаке. Экспериментальные: Cloud Hypervisor, OpenShell (через свой gateway это контейнеры на ядре хоста, не VM; без рабочего стола, снимков и форков) и boat.dev. Один MCP-сервер может вести несколько хостов сразу. Клиенты в README: Claude Code, Codex, Cursor, opencode, pi и любой MCP-клиент. Пакет — boxery-vm. Инструменты агента: оболочка и файлы (vm_bash, vm_read, vm_write, vm_edit, vm_jobs, vm_copy), рабочий стол и браузер (vm_screenshot, vm_click, vm_type, vm_key, vm_scroll, vm_browser), жизненный цикл (vm_manage, vm_info: создать, форкнуть, снять snapshot, откатить, удалить) и доступ (vm_grant, vm_lease). В README проект помечен как ранний: возможны шероховатости и ломающие изменения между релизами.

Кому: тем, кто хочет отдать агенту отдельную Linux-VM или песочницу и не класть туда свои ключи. На что смотреть: docs/mcp.md, docs/install.md (выбор бэкенда) и docs/security.md. saas-growth-agents: SOP роста SaaS для агента

Pluviobyte/saas-growth-agents в описании GitHub отдаёт агенту рутину роста SaaS: радар новых запросов, поиск сайтов по ключевым словам, бэклинки конкурентов, отправка в каталоги и пакет социального анализа со скиллом комментариев Douyin. В описании перечислены Grok Bot, Muse, Dot, Hermes, OpenClaw, Claude Code и Codex. По README это SOP и скрипты, которые автор гоняет для своих SaaS на зарубежных рынках. Три правила из README: скрипты делают детерминированную работу (сбор, дедуп, скоринг, лог); агент читает результат, разбирает и докладывает, а если данных нет — говорит об этом; траты, отправка наружу и удаление ждут подтверждения человека. Поправка человека становится новым правилом в скиллах.

  • New-term radar. В таблице README — три отчёта в день о новых поисковых терминах: новые AI-продукты, модели, мемы, шаблоны. Источники в README: Google Trends, карты сайтов конкурентов, новые листинги каталогов, Product Hunt, GitHub Trending, Reddit и TikTok.
  • Site ops. Ему отдают ключевые слова и продукт. Он ищет сайты, которые конкурируют за запрос, смотрит их DR и бэклинки, ежедневно пишет метрики своего сайта, отправляет в бесплатные каталоги по правилам и ведёт лог.
  • Social analysis pack. По ссылке забирает оригинал (X, Douyin, RedNote, YouTube, WeChat или веб-страница), кратко пересказывает, выписывает, что можно поправить в своих SOP, и раскладывает по темам. Для Douyin может забрать раздел комментариев. Скилл лежит в bots/social-kb/douyin-comments/. README пишет, что этот модуль не ходит во внешний API данных и работает в своём залогиненном браузере.

Отдельное дополнение, extras/trade-radar, смотрит движение цен и события и присылает разбор. В README сказано, что он только анализирует и заявок не выставляет; в его коде нет размещения ордеров. Внешние данные роста идут через сервис AIsa: в README перечислены SEO (DataForSEO SERP и Google Trends, Ahrefs), соцсети, веб и источники торгового радара. У запроса есть потолок цены, превышение отклоняется, перед вызовом можно спросить цену флагом --quote. Границы из README: не решает CAPTCHA, не вводит пароли и не регистрирует аккаунты; в каталоги идут только бесплатные площадки без требования обратной ссылки. Описания задач внутри репозитория на китайском; README говорит, что агент их читает и отвечает на языке человека. В README есть реферальные ссылки на регистрацию агента и на AIsa — в этот выпуск они не входят. Ссылка одна: репозиторий на GitHub.

lot-map: карта рядом с чатом Claude Code

alexeyw/lot-map в описании GitHub — живая карта рядом с чатом: видно, что делает Claude Code. Tool calls, шаги модели, hooks, skills и subagents загораются по ходу. Только локально, на пяти языках. По README это плагин Claude Code. Панель открывается сама при старте сессии. В терминале нужна ширина не меньше 144 колонок, рисуется текст; иначе команда /lot-map. В десктоп-приложении маркетплейс добавляют как alexeyw/lot-map, затем ставят плагин. README указывает сборку и проверку на Claude Code 2.1.321 на macOS и пишет, что пользователи сообщают о работе на Windows.

Станции на карте: You (ваши сообщения), Model (запрос к модели и сжатие контекста), Memory, Files (Read, Write, Edit, Grep, Glob и shell, который только читает или правит файлы), Shell (остальные команды), Network (web, MCP и команды вроде curl, gh, ssh, git push), Browser, Agents (subagents и их вызовы), Skills, Hooks (отказ, вопрос разрешения, добавленный контекст). Импульс уходит, когда вызов начался, и возвращается, когда закончился. Отказ и ошибка рисуются красным. Станция Shell определяется по имени команды, не по тому, что скрипт сделает внутри. Языки подписей: en, ru, es, fr, de.

README отдельно описывает, чего мод не делает: сетевых запросов нет, файлы он не читает, процессы не запускает, модель не вызывает и в разговор ничего не добавляет. Строки живут только текущую сессию. Между сессиями хранится имя модели, последней использованной в папке, чтобы показать смену. Подпись — имя, не содержимое: у файла последние две части пути, у адреса только хост, у shell — короткое описание или имя команды, не командная строка. Разбор имён — функция classify в hooks/map.ts. Маркетплейс с этого репозитория следит за веткой main; README советует читать diff перед обновлением. Сбой карты до вызова инструмента и до хода модели не доходит.

На что смотреть: станции и hooks/map.ts, плюс то, что мод локальный и подписи не содержат текста файлов и командной строки.
